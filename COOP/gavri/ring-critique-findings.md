# Ring-mesh SECURE-ring — adversarial critique findings (panel)

Panel: codex + 3 Claude critics. Status: **crypto ✓**, **throughput/on-device ✓**, topology (running), codex (running).
Marathon: `mrun-e8c0d6b8a851` (feature `meshtest-securering`). These findings drive the design revision BEFORE any implementation.

## A. CRYPTO & CHAIN INTEGRITY
- **C1 (CRITICAL)** — sole start/stop node is verifier + persister + seq/nonce/ts author + first signer, no external witness → it can silently **truncate / omit / roll back** cycles and re-verify clean; "tamper-evident" is false against that node. **Fix:** every K cycles all four nodes **co-sign a checkpoint** `{run_id, max_seq, head_fp}` published to an independent witness (mailbox + a 2nd node's disk); each signer keeps a **monotonic per-run high-water seq and refuses to sign seq ≤ seen** (kills rollback).
- **C2 (CRITICAL)** — pubkeys distributed over the **unauthenticated** mailbox → provisioning MITM forges any node's identity (the shipped amulet learned this: `AmuletVerifier.cs:45-46,97-101` pins a trust anchor; the ring has none). **Fix:** pin the **ordered 4-key roster** via an out-of-band-verified `SHA-256(sorted pubkeys)`, embed that roster-hash in genesis `M_1` so the whole chain is bound to the exact key set.
- **H1 (HIGH)** — signed bytes omit signer id / position / run_id / roster → strippable to 3 hops, one node filling two positions, cross-run splice (genesis prev_fp = 0x00*32 identical across runs). **Fix:** `Sign(sk_k, "glp-ring:v1" ‖ run_id ‖ seq ‖ k ‖ pubkey_k ‖ canonical(M) ‖ prefix_sigs)`; verifier requires **exactly the ordered roster, count==4, distinct signers**.
- **H2 (HIGH)** — plaintext TCP → the "secret nonce" property is **false** (passive WiFi sniff reads it); no channel binding. **Fix:** each hop over **identity-keyed TLS/Noise**; delete the secrecy claim; freshness comes from signed nonce+seq+run_id.
- **H3 (HIGH)** — single entropy source (start RNG fully controls the transcript). **Fix:** each node contributes entropy; verifier persists + enforces **per-run nonce-uniqueness**.
- **M1** — FP = SHA-256(raw concat), no domain tag, length-extension-exposed on the bare head-FP checkpoint. **Fix:** `FP = SHA-256("glp-ring-fp:v1" ‖ …)`; never a bare FP as authenticator.
- **M2** — FP hashes raw sig bytes → any Ed25519 malleability = two valid FPs (chain fork). **Fix:** pin a non-malleability golden vector for the BouncyCastle build; FP over canonical(M)+hash(pubkey,msg), not raw sig bytes.
- **M3** — amulet key is **ephemeral per app-launch, in-memory only** (`IDeviceSealKey.cs:29-44`) → orphans sigs across a multi-hour run; cross-protocol reuse. **Fix:** dedicated **stable ring keypair** per node.

## B. THROUGHPUT / PERSISTENCE / ON-DEVICE
- **Arithmetic the doc skips:** 4 signs + **10 verifies** (chained-sig) + 4 WiFi hops/cycle → ~16–31 ms/cycle → **~50 cyc/s → 1M ≈ 5.6 h nominal, 8–15 h+ realistic.** Bottleneck = the **4-hop WiFi round-trip**, not Ed25519.
- **C1 (CRITICAL)** — strict per-cycle `prev_fp` chain forces **pipeline-depth-1** (one token in flight); can't pipeline without breaking the chain. **Fix:** batch **B nonces per round-trip**, **Merkle-root over the batch**, chain the roots (B≈256–1024 → thousands/s, tamper-evidence preserved). *If the intent is to stress the network over hours, keep serial but own the 5–12 h.*
- **C2 (CRITICAL)** — halt-on-bad-sig conflates **tamper (halt)** with **transient link-drop (don't halt)**; `FP_N` undefined if cycle N never returns → **stall / never finishes**. **Fix:** bad-sig ⇒ halt+preserve; timeout/drop ⇒ retry k× fresh nonce → **deterministic FAIL record** (`FP_N=H(partial‖FAIL)`) so every seq gets exactly one record and the chain never gaps; + watchdog + TCP keepalive + idempotent straggler-drop.
- **C3 (CRITICAL)** — multi-hour loop gets **Doze'd / App-Standby'd / killed / battery-drained / thermally throttled** on Samsung; the budget **Tab (SM-X130) is the rate-limiter** and drifts slower as it heats. Crypto itself is fine (pure-managed BouncyCastle under W^X/no-JIT). **Fix:** run inside the MAUI app as a **foreground Service + partial wakelock**, **battery-optimization exemption** on both Samsungs, both on **chargers with active cooling**, loop on a **background thread** (reuse #020 dedicated-thread), treat the Tab as bottleneck (drop/swap if possible).
- **H1** — storage estimate off ~10–20×: 1M records ≈ **370–700 MB** (sigs are the bulk), not "tens of MB". **Fix:** fixed-width **binary CRC-framed** records; push sigs to a sidecar; chain file `{seq,prev_fp,fp}` ≈72 B → **~72 MB**.
- **H2** — fsync-per-cycle is the wrong durability point (adds to the serial path for no benefit; it's a re-runnable test). **Fix:** **group-commit** the bulk log every K + fsync a tiny **head-FP checkpoint** more often.
- **H3** — no torn-write/crash-resume design. **Fix:** adopt yngenios verbatim — **10-byte CRC32 frame (magic‖len‖crc‖payload), replay from 0, stop at first bad frame, fail-closed**; resume from last valid `{seq,fp}`, re-broadcast authoritative `(seq,prev_fp)`, fresh nonce.
- **H4** — shipped `Ed25519Signer` **re-expands the private scalar (SHA-512 + base-point mul) every call** + per-call allocations → GC thrash on the tablet's small heap. **Fix:** cache an expanded key object per node + preallocate message/sig buffers + reuse the CBOR writer, once at setup.
- **M2** — WiFi **airtime (per-packet)**, not bandwidth, is the pipelined ceiling → batching beats fine-grained pipelining; use **5 GHz**, keep nodes close to the AP.

## C. TOPOLOGY & TRANSPORT  (the plan-changing critique)
**Thesis:** the proposal rebuilds — over raw `nc` TCP — a strictly weaker copy of a mesh + router + reliability layer + chained-signature scheme **that already ship and are CI-tested**, so 1M green cycles prove the throwaway, not the product. A cross-host mesh test over the real stack is **already specified**: `glpnet/specs/050-glp-native-quic-link/contracts/mesh-test-harness.md`.
- **C1 (CRITICAL)** — single unidirectional ring = zero path diversity, every node a SPOF; §4.2/§9 make a dead node fatal by design. Shipped `Olamnit.Kernel/Mesh/MeshNodeRuntime.cs` + `DistanceVectorRouter.cs` = DSDV/Bellman-Ford multi-hop mesh (split-horizon, poison-reverse, reconverge on link change, exactly-once across a relay kill via `_pending` + `IdempotentSink`). **Fix:** drive the token **over the DV mesh** wired as the redundant "two-triangles" graph; kill a node ⇒ reroute, not halt — *that* is worth 1M cycles.
- **C2 (CRITICAL)** — raw `nc` exercises none of the product. Ship transport = `glp_link/transports/QuicTransport.cs` (real HTTP/3 QUIC, mutual SPKI-pinned certs `base64(SHA-256(SPKI))`, persistent idle link), `glp_quick_host` is already a multi-accept **mesh router**. The chained-sig is a re-impl of `glp_crdtmsg/sig/Seals.cs` `SealSet.Seal/Verify`. **Fix:** run nodes as shipped endpoints (`glp_quick_host` on PCs, MAUI glp-quick client on handsets), express the ring as crdtmsg envelopes, sign with `SealSet` over `MessageCodec.Canonical`, adopt spec-050's harness as the skeleton + raise the cycle count.
- **H3 (HIGH)** — no liveness/failure detection; §9 conflates bad-sig with dead-peer. Shipped `MeshSendOutcome.Unreachable` (bounded `RouteWaitTimeout`, never hangs) + `MarkDown`/reconverge; `SealSet.Verify` returns false (distinct from transport fault). **Fix:** bounded per-hop timeout → closed outcome; bad-sig ⇒ halt-inspect, peer-down ⇒ reroute+count. Reuse `MeshSendOutcome`/`LinkFault`.
- **H4 (HIGH)** — raw-IP identity is fragile (olamnit is `.129`/`.136`/`.143` across three docs!) and the ring *order* isn't bound to identity (per-hop sigs sign content, not routing position → live validly-keyed hops can be reordered). **Fix:** address by pinned logical id via `glp_crdtmsg/route/Addressing.cs` `AddressBook.Resolve` (authenticated, loud-fail-no-fallback, SC-007); bind ring order into a **signed caveat**. Reconcile the olamnit IP.
- **H5 (HIGH)** — WiFi-TCP-via-nc exercises neither shipped leaf. glp-quick is **QUIC-only and client-only** (`GlpQuickLinkTransport.ListenAsync` throws — "never listens, never routes") → a handset can dial next but can't accept prev → breaks a naive ring. **Fix:** to prove #023 transport ⇒ QUIC **hub/star** (glp_quick_host is the router), not a ring; to prove BLE ⇒ ride `MeshNodeRuntime` over the L2CAP leaf (gavri has the radio) where accept+send both exist behind one seam. Retire raw `nc` after the smoke test.
- **M6** — one serial TCP byte-stream per hop head-of-line-blocks the ring; `ts:` across 2 PCs + 2 Android isn't monotonic. **Fix:** terminate persistent links on the QUIC multi-accept server (slow hop backpressures one link, `InboundOrdering` bounded reorder + per-link window); order/dedup by per-origin `MessageId=(origin,seq)`, never `ts`.
- **M7** — reusing glp-quick: `GlpQuickLink.SendProbeAsync` **never reads a reply** → un-acked sends counted as hops → a green 1M run could silently blackhole. **Fix:** a hop is "ok" only after the next hop's ack round-trips (existing `correlationId` reply, or `MeshNodeRuntime` delivery callback).

## D. CONVERGENT SYNTHESIS (3 of 4 critics agree; codex pending)
**Do NOT implement the throwaway `nc` ring.** Build `meshtest-securering` **on the shipped, CI-tested stack**:
1. **Transport/topology:** run the 1M-cycle soak over **QUIC/WS via `glp_quick_host` + crdtmsg envelopes**, or the **`MeshNodeRuntime` DV mesh** for the redundant "two-triangles" topology (reroute-not-halt). Use `specs/050-.../contracts/mesh-test-harness.md` as the skeleton. Retire raw `nc`.
2. **Crypto:** sign with the shipped **`SealSet`** (don't recode) but **add the hardening the ad-hoc design was missing**: OOB-pinned ordered roster hashed into genesis (C2), all-node co-signed **witness checkpoints** + monotonic per-run seq (C1), full binding of run_id/position/roster (H1), identity-keyed channel (already SPKI-pinned in QUIC — H2), dedicated stable ring key not the ephemeral amulet key (M3), domain-separated FP (M1).
3. **Throughput/durability:** **batch B cycles/round-trip + Merkle-root chaining** (network-bound 5–12 h → crypto/disk-bound minutes) (thruput-C1); **split fail policy** + deterministic FAIL record + watchdog/keepalive (thruput-C2/topo-H3); **CRC-frame group-commit + head checkpoint** crash-resume (thruput-H2/H3); cache expanded Ed25519 key (thruput-H4).
4. **On-device:** MAUI **foreground service + wakelock + battery-opt exemption + charger/cooling**; Tab is the rate-limiter (thruput-C3).
5. **Identity:** authenticated `AddressBook`/`@name` resolution, reconcile olamnit's IP, bind ring order into a signed caveat (topo-H4).

**Implication for the olamnit-leads split:** olamnit's stack ALREADY implements most of the "underlying capability" (QUIC transport, SealSet, DV mesh, spec-050 harness). The meshtest-securering is largely **integration + hardening on top of olamnit's shipped code**, not new infrastructure — which should shape olamnit's forthcoming design.
