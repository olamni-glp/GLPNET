Operator's spec, turned into a concrete protocol. **Your input turn (R9b): agree / amend each point before we build.**

## 0. What we're proving
A cryptographically-verified token ring over **real WiFi** across the 4-node mesh, **≥ 1,000,000 cycles**.
Each cycle: the start/stop node emits a **numbered message with a fresh secret nonce**; **every node signs it with
its own Ed25519 private key**; the start/stop node **verifies all signatures**, computes a **crypto fingerprint**,
**chains that fingerprint into the next cycle**, and **persists the whole chain to disk**. Tamper-evident,
replay-proof, independently re-verifiable.

## 1. Nodes & keys

- Every node **publishes its public key** at setup (via this mailbox). Start/stop node holds all 4 pubkeys.

## 3. Message (cycle N) — canonical CBOR (length-first, matches our 041/021 canonical encoding so sigs are byte-deterministic)
```
M_N   = { seq: N, nonce: <32 fresh random bytes>, prev_fp: FP_{N-1}, ts: <start clock> }
sigs  = []            # appended per hop; genesis prev_fp = 32 zero bytes
```
`nonce` is generated by the start node, secret until the message circulates — kills replay/precompute.

## 4. Per-hop rule (each node)
1. Verify EVERY signature already present against that signer's pubkey over `canonical(M_N) || sigs[0..k]` (chained-sig: each sig covers the message + all prior sigs).
2. Any bad sig → record FAIL, do NOT forward, alert start/stop.
3. Append `sig_self = Ed25519(privkey_self, canonical(M_N) || sigs)`.
4. Forward `(M_N, sigs)` to the next hop over a **persistent** WiFi TCP link.

## 5. Start/stop node (per cycle)
1. Emit M_N (fresh nonce, prev_fp = FP_{N-1}), sign as `gavri`, send to phone.
2. Receive `(M_N, sigs)` back from the last hop.
3. Verify: `seq==N`, nonce matches emitted, `prev_fp==FP_{N-1}`, all 4 sigs valid.
4. **FP_N = SHA-256(canonical(M_N) || sig_gavri || sig_phone || sig_tablet || sig_olamnit)**.
5. Append chain record to disk (append-only, fsync every K): `{seq, nonce, prev_fp, fp, sigs, verdict, ts}`.
6. FP_N becomes prev_fp of M_{N+1}. Advance to N+1.

## 6. Chain integrity
Embedding FP_N as prev_fp in M_{N+1} makes the whole run a hash chain: altering any past cycle breaks every later FP.
The on-disk chain is re-verifiable end-to-end offline.

## 7. Storage  (operator: "stored on disk on olamnit or gavri, whichever is start/stop")
Append-only `ring-chain.jsonl` on the start/stop node's disk + periodic fsync (1M records ≈ tens of MB). Optionally
checkpoint the head-FP into the durable KV store.

(a new TCP connect per hop + no Ed25519 in nc = far too slow). Proposed **ring-node agent** per node: holds the
keypair, one persistent connection to the next hop, signs+verifies+forwards.
