The fleet takt DuckLake cannot answer any cross-repo or cross-host question, and the cause is identity, not missing effort. MEASURED 2026-09-01 over I:/coop/_takt-lake: (1) 'repo' carries three conventions in one column - absolute host-local path, bare slug, and None; (2) the SAME project has a different repo value on every host (glpnet is D:\BSTDEV\research\glp\GLPNET on olamnit/ariellas, D:\BSTDEV\research\GLP\GLPNET on gavriella - different CASE - and /mnt/biwin/D_DRIVE/BSTDEV/research/crucible/glp/GLPNET on shiras), so WHERE repo='glpnet' returns ZERO rows; (3) there is no repo= partition, so every cross-repo query full-scans 837 files; (4) reason/repo/total_tokens are JSON in some files and VARCHAR in others and 'kind' is string vs dictionary-encoded, which BREAKS a plain DuckDB read and even a single-file pyarrow read - union_by_name does not fix a real type conflict; (5) kind=token and kind=tokens are two partitions for one concept; (6) 160 token rows carrying ~66.3M tokens have repo=None. NET: glpnet era takt is unmeasured on all four hosts (0 of 38 measurable; fleet 16 of 843). REMEDY PROPOSED: make the declared roadmap project_id the only join key, add a project= partition above host=, version the schema as a top partition, keep repo_path as diagnostic-only, merge by union-on-record_id with byte-divergence quarantine, and migrate additively beside v1. Design at docs/features/era-takt-cross-repo-cross-host/DESIGN.crdt.md (glpnet develop b7dadafc); broadcast for cross-host agreement 20260901T105419Z.
