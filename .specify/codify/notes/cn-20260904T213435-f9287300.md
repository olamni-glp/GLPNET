The QUIC listener was verified by BINDING a port rather than by asserting IsSupported, and that same
instinct — run it, do not reason about it — is what exposed Q-GLPNETA21-01. Nobody would have
questioned `CreateDevCert`: it is well named, correct for its purpose, and used exactly as intended
in its own tests. What made the defect visible was running the unchanged probe five times on one
unchanged host and noticing that the pin moved every time. Reading the source only told us WHY,
after the measurement had already told us THAT.

Two derived lessons, both cheap to reuse:

1. **Repeat-invariance is a test you can run on almost anything.** For any value a system publishes
   as an identity — a pin, a node id, a device fingerprint — run the producer N times and assert one
   distinct value. It costs a loop and it catches an entire class of "works until you restart" bugs
   that unit tests miss, because a unit test builds its own material in-process and never restarts.

2. **A defect can live entirely in the ADOPTION of a component, not in the component.** The fix
   changed no line of `CreateDevCert`; it added the sibling that should have existed and re-pointed
   the caller. When a component is blameless but the outcome is wrong, look at who adopted it for
   what, before rewriting it.

The adversarial review then earned its place twice: cycle 1 found a concurrent-remint race the
tests did not model, and cycle 2 found that the file ACL was applied AFTER the key bytes were
written. Both were real, both were fixed, and cycle 2's verdicts (CLOSED/PARTIAL/OPEN per prior
finding) were more useful than a fresh review would have been — asking "is finding N closed?" is a
sharper question than "review this again".
