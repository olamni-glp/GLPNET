2026-08-18. I reported '077 is released but 34 commits were never merged into develop' as a headline defect and recommended a PR. It was false: local develop was 50 commits behind origin/develop, and 077 is in fact FULLY MERGED (merge-base --is-ancestor returns true; PR #153 state MERGED). The same stale ref also inflated the unmerged-branch inventory from 6 to 9. This is the FOURTH stale-artifact false conclusion in this programme - after a stale memory brief, a stale 3rtask index, and a 37h-stale binary - and the second I produced myself. The existing rule 'date-stamp every measured claim; a claim older than the session is a hypothesis until re-run' did not catch it because a git ref carries no visible timestamp at the point of use. RULE EXTENSION ADOPTED: never measure against a local tracking branch. Fetch first and compare against origin/<branch> explicitly, and state which ref and which sha the measurement used. WHAT SAVED IT: nothing automatic - I only caught it because merge commits for PRs #154-#157 appeared in a 'not in develop' list, which is impossible for merged PRs, and I followed the contradiction instead of reporting the count.
