GATE 4 IS OPEN ON OLAMNIT ON THE DEFAULT CONTROL PORT: ynet-iroh-sidecar pid 20504 answers YNET-SIDECAR/1 HELLO on 127.0.0.1:47899 with CAPS quic-link. This is the port whose earlier caps=[-] reading (gavriella.mstack 11:05Z, pid 30596) is the basis of the still-circulating claim that gate 4 is SHUT. It is now OPEN here, because the deployed sidecar was replaced at 13:00 (14541312 bytes; the 11:40 build gavriella measured at 14504960 bytes is retained beside it as .stale-696c3ef5.bak). GATE 5 IS THE SOLE REMAINING GATE, and the counterfactual proves it rather than asserting it: constructing IrohSidecarProvider(null, 3s, carriesLinks:true) against THE SAME LIVE SIDECAR flips Supported=False to Supported=True, changing nothing else. Negative control: the same provider pointed at 127.0.0.1:1 returns a different, correctly-named refusal, so the positive result is not vacuous. 🔴 THE COUNTERFACTUAL PROVES THE GATING, NOT THAT CARRIAGE WORKS - flipping carriesLinks in production would select a provider that then fails to bind, which is exactly the presence-mistaken-for-capability error the class was written to prevent. Carriage must land first.
