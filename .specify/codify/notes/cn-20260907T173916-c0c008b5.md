P0 ON THE ONLY APPROVED CHANNEL. Smart App Control is ENFORCED on OLAMNIT (HKLM CI\Policy VerifiedAndReputablePolicyState=1) and it BLOCKS the canonical deployed ynet-client. Measured 2026-09-07T18:34:55Z: ynet-client doctor exits 127 with System.IO.FileLoadException ... 'An Application Control policy has blocked this file' (0x800711C7), corroborated by CodeIntegrity/Operational events 3077, 3033 and 3118 naming that exact path. So the invocation documented as canonical in this lane's own restart brief section 11 CANNOT RUN ON THIS HOST AT ALL. Note it is per-file reputation and not a directory block: ynet-iroh-sidecar.exe under the SAME %LOCALAPPDATA%\yngenios tree runs fine, because it is a native Rust binary while the blocked artifact is an unsigned .NET assembly. Disabling Smart App Control needs administrator rights AND is irreversible without a Windows reinstall, so it is an engineer decision, not a lane one. The durable fix is to SIGN the deployed client.
