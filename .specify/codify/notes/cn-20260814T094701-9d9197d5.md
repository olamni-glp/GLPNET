Two unified-suite runs went concurrent during 076 implement verification: a background run was killed by the harness but orphaned its process tree, and the next run then hit Git-Bash 'fork: Resource temporarily unavailable' / 0xC0000142 and died mid-suite. Force-killing the orphaned trees left host state that made Section I cross-runtime link_both_ways C-to-G fail reproducibly (WSAECONNABORTED) when it had passed 4/4 in the same session's baseline. Cost: three aborted verification runs and an unattributable-looking regression that took a Dart-free-path proof to clear. Wanted: the suite should refuse to start when another run holds a lockfile, and long verification runs should be launched detached from the agent task lifecycle (Start-Process + done-sentinel worked) rather than as a killable background task.
