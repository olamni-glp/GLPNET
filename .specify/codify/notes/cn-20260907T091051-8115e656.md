Windows Firewall rule sprawl from scratchpad builds silently decides whether a lane's QUIC probe is reachable. 40 inbound rules on this host cover 16 distinct probe binaries; 32 point at per-session Claude scratchpad paths that no longer exist, and exactly ONE binary carries a Block rule. Windows evaluates Block before Allow and a later Allow for the same program cannot override it, so that binary binds successfully, reports a healthy listener, and is unreachable from every peer - the lane would reasonably conclude QUIC does not work. The sprawl is what made the single Block invisible. Rules are auto-created on first bind and clicking Cancel creates a permanent Block nobody intended. Also measured: a QUIC listener binds on the fleet-reachable LAN address, not only loopback - so 'YNET binds loopback only' is true of the Python board and false of the C# transport, two different components. And the limit: a bind is not reachability, so no cross-host claim can rest on a local bind.
