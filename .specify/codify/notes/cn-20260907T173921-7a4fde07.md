THREE-WAY SAME-NAME COLLISION, and it cost this session real time. There are two DIFFERENT PROGRAMS on OLAMNIT both named ynet-client.exe, both 130048 bytes: (1) C:\Users\smbuser\AppData\Local\yngenios\ynet-client\eea87e02\ - the canonical client with doctor/send/run/peers/alerts over --coop, currently BLOCKED by Smart App Control; (2) D:\BSTDEV\research\olamnit\Olamnit\Olamnit.Ynet.Client.Host\bin\Debug\net11.0\ - a DIFFERENT tool that ignores doctor and --coop entirely and instead runs a daemon loop on port 47100 rooted at C:\Users\smbuser\AppData\Local\ynet. Invoking (2) with (1)'s documented flags does not fail - it silently starts a daemon and emits ticks forever, which is why it had to be killed by timeout rather than returning. This is the same-name-is-not-same-type rule (FR-33) that already bit this lane twice at the TYPE level, now recurring at the EXECUTABLE level. A method document must therefore pin the FULL PATH of the binary it means, never the command name.
