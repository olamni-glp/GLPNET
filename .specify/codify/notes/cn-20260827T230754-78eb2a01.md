GAVRIELLA resumes 15 repo lanes after reboot with ZERO manual steps: a BK-OnRestart scheduled task fires at logon + 45s and relaunches every lane as a Windows Terminal tab via 'claude --continue --autocompact 1000000', resuming each thread MID-CONVERSATION instead of summarising. Gavriella uses TWO windows (layout TwoWindows, per-host via layoutByHost): window 1 carries ospark, tefl, hatzinor, olamnit, buildkit, qhstate, yngraw; window 2 carries crucible, glpnet, lejepa, mstack, yngwin, yngapp, ynlin, yngorg. Order and window allocation are part of the contract, not cosmetic. WHY IT IS A WIN: the mechanism encodes four traps that each silently produce a plausible-looking failure. (1) SILENT-NEW-SESSION: 'claude --continue' does NOT error when no stored session exists for the cwd, it silently starts a brand new empty one, which after a reboot is indistinguishable from a successful resume until the context is gone; so every lane's session store is validated BEFORE launch and re-read AFTER, and a different sessionId is reported as FAILURE not resume. (2) BARE-SEMICOLON: wt's command separator must reach wt as a bare ';' token - a backtick-escaped one arrives literally and produces tabs that open and run NOTHING (measured in the reference lane: 12 tabs, 0 claude processes), so verification counts PROCESSES, never trusts the message. (3) TWO DIFFERENT MOUNT WAITS: local repo paths are REQUIRED and refused if missing, network shares are OPTIONAL and launch anyway, because in a fleet-wide reboot the share host is down too and blocking means the restart never runs. (4) NEVER --fork-session: it mints a new session id and continues a COPY, which is not continuing. AUTO-INSTALLABLE ON ANY HOST: 'pwsh -File scripts/onrestart-launch.ps1 -Install' resolves its own path and the running pwsh portably, registers the at-logon+45s task for the current user, and is idempotent via -Force. Verified on GAVRIELLA 2026-08-28: 15 requested, 15 will launch, 0 refused, exit 0.
