REPRODUCED 2026-08-17T20:40Z on GAVRIELLA. pip install --force-reinstall of buildkit-cli 2026.8.15.1 built the wheel, then failed during 'Uninstalling buildkit-cli-2026.8.15.1' with OSError WinError 32 - buildkit-marathon.exe locked by another lane's process (pid 5768, 6s old). pip had ALREADY removed package content before reaching the locked .exe shim, leaving user-site buildkit_cli importable but buildkit_cli.marathon MISSING plus a rollback artifact '~-db-runner' inside core_pack. This is how the toolchain broke at ~20:15Z and killed a marathon capture mid-batch; every buildkit entrypoint on the host failed for ~25 min. TWO LESSONS: (1) an install must REFUSE while any buildkit*.exe is running, rather than half-uninstall; (2) buildkit_cli resolves subpackages dynamically via core_pack, so 'ls shows 1 entry' is NORMAL - I initially misdiagnosed a healthy layout as gutted, and only an IMPORT test distinguished the healthy deploy-home venv from the corrupt user-site install. Diagnose by execution, never by directory listing - the same class as the stale-binary and stale-index errors this programme keeps hitting.
