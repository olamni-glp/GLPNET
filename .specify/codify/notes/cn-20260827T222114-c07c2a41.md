MECHANISM WORTH PROMOTING TO A BUILDKIT FEATURE. bk-onrestart restores a whole multi-lane fleet after reboot as terminal tabs running 'claude --continue --autocompact 1000000', resuming each thread MID-CONVERSATION instead of summarising. Measured on shiras 2026-08-27: layout=1, window1=15 tabs, window2=0, skipped=0, expected 15 claude processes; preflight exits 0 SAFE TO REBOOT. WHY SHIP IT RATHER THAN COPY IT: (1) WINDOW TOPOLOGY IS PER HOST - ariellas uses TWO windows (agent lanes in one, repo lanes in the other), shiras uses ONE window for all lane tabs; the config already models this as windows[] plus a layout 1|2 switch, so topology is DATA not a fork. (2) TWO TRIGGERS ARE INSTALLED ON PURPOSE - a systemd user unit AND an XDG autostart entry, because XFCE never activates graphical-session.target; a double-fire is absorbed by a guard-minutes no-op whose marker is written AFTER launch so a crash cannot lock the fleet out. (3) CROSS-PLATFORM BY RE-EXPRESSION, NOT PORT - the PowerShell original drives wt.exe/Get-Process; the Linux peer keeps MECHANISM and GUARDS verbatim and re-expresses only terminal driver, process check, trigger. (4) EVERY GUARD ENCODES A MEASURED FAILURE: a missing session store makes claude --continue silently start a BRAND NEW EMPTY session indistinguishable from a resume (so skip+report, never launch); --fork-session is never passed (it continues a COPY); autocompact pinned to CLI max so only later compaction can summarise; success VERIFIED BY COUNTING PROCESSES because 12 tabs opening and running nothing was measured on Windows while the script reported success. (5) preflight is an EXECUTABLE reboot gate (exit 0 = safe), not a sentence typed optimistically. GAP TO CLOSE: trigger install is hand-run per host - make it AUTO-INSTALLABLE ON ANY HOST (detect terminal driver + init system, install both triggers, auto-register lanes by capturing every repo under a root that has a session store).
