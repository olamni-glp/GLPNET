MECHANISM WORTH PROMOTING TO A BUILDKIT FEATURE. bk-onrestart restores a whole multi-lane fleet after reboot as terminal tabs running 'claude --continue --autocompact 1000000', resuming each thread MID-CONVERSATION instead of summarising. RETRACTED MEASUREMENT (2026-08-30, codexreview 20260831T100556Z finding 2): the 2026-08-27 line 'layout=1, window1=15 tabs, skipped=0, preflight exits 0 SAFE TO REBOOT' is DISPROVEN and must NOT be read as validated evidence. Re-measured BARE on shiras 2026-08-30: preflight exits 1 (NOT SAFE TO REBOOT); 18 lanes registered, not 15; 2 of them (claudesat, game_dev_demo) have NO session store yet are reported as '0 will be skipped'; the systemd unit carried NO [Install] section at all (is-enabled=static, so it could never fire at logon) plus ~65 lines of pasted systemctl status output that systemd refused to parse. The earlier exit-0 reading came from piping the gate: 'preflight 2>&1 | tail' returns tail's 0 while printing every FAIL. See docs/research/RESTART-PREP-shiras-glpnet-mrun-f77f62158255.md section 0. WHY SHIP IT RATHER THAN COPY IT: (1) WINDOW TOPOLOGY IS PER HOST - ariellas uses TWO windows (agent lanes in one, repo lanes in the other), shiras uses ONE window for all lane tabs; the config already models this as windows[] plus a layout 1|2 switch, so topology is DATA not a fork. (2) TWO TRIGGERS ARE INSTALLED ON PURPOSE - a systemd user unit AND an XDG autostart entry, because XFCE never activates graphical-session.target; a double-fire is absorbed by a guard-minutes no-op whose marker is written AFTER launch so a crash cannot lock the fleet out. (3) CROSS-PLATFORM BY RE-EXPRESSION, NOT PORT - the PowerShell original drives wt.exe/Get-Process; the Linux peer keeps MECHANISM and GUARDS verbatim and re-expresses only terminal driver, process check, trigger. (4) EVERY GUARD ENCODES A MEASURED FAILURE: a missing session store makes claude --continue silently start a BRAND NEW EMPTY session indistinguishable from a resume (so skip+report, never launch); --fork-session is never passed (it continues a COPY); autocompact pinned to CLI max so only later compaction can summarise; success VERIFIED BY COUNTING PROCESSES because 12 tabs opening and running nothing was measured on Windows while the script reported success. (5) preflight is an EXECUTABLE reboot gate (exit 0 = safe), not a sentence typed optimistically -- BUT it MUST BE RUN BARE: a pipe returns the pipe's status and hides every FAIL, and three of its probes are themselves false positives (it greps the unit FILE for WantedBy so it cannot see a drop-in; it compares ExecStart first-tokens so a 'bash -lc' wrapper reads as a second launcher). Reported to the buildkit lane. GAP TO CLOSE: trigger install is hand-run per host - make it AUTO-INSTALLABLE ON ANY HOST (detect terminal driver + init system, install both triggers, auto-register lanes by capturing every repo under a root that has a session store).
