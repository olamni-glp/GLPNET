IrohSidecarProvider.cs discloses its gap as 'no Rust toolchain exists on OLAMNIT (cargo/rustc absent, measured 2026-09-05)'. The disclosure is honest, dated and host-named - and it was STILL read fleet-wide as 'iroh is unbuildable', because the consuming lanes quote the conclusion (Probe reports unavailable, chain falls to msquic) and not the host qualifier. MEASURED SHIRAS 2026-09-07T10:28Z: cargo 1.98.1 and rustc are present at /home/shira/.local/bin and 'cargo search iroh' resolves iroh = 1.1.0, so the one stated blocker is ABSENT ON THIS HOST. Negative control worth keeping: a direct curl to the crates.io API returns 403 from here, so a curl-based reachability probe would have reported this host incapable and reproduced the same false generalisation. IMPROVEMENT: a disclosed gap must state its SCOPE in the same sentence as its conclusion ('unavailable ON HOSTS WITHOUT cargo' not 'unavailable'), and any allocation derived from it must name a host chosen by a recorded probe.
