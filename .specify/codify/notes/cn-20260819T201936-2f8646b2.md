3rtask run 20260819T162016Z-6e73 derived DEFECT D1 at high confidence: the bk-scheduler skill contract states verbatim 'There is no distribute and no allocate verb' and documents a 10-command surface, while the live 2026.8.19.1 binary exposes allocate plus six further omitted commands. I designed requirement SR-7 assuming the shipped /bk-guards template-contract check would catch exactly this. It does not. Run against the scheduler skill it reports status=clean, findings=0, coverage checked=true; run with --all it reports checked=true on 62 of 62 skills with ZERO findings. This is NOT a false green - the guard's declared scope is one-directional, documented-step -> CLI (an unknown subcommand or flag the skill USES). D1 is the reverse direction, CLI -> documentation (a verb the CLI HAS that the doc denies or omits), which is outside what it claims to check. Two consequences. (1) SR-7 must be amended: the guard needs a reverse-direction check, and a doc that makes a NEGATIVE existence claim ('there is no X verb') must be verifiable against live introspection. (2) A guard reporting checked=true/clean on 62 units while a high-confidence contract defect sits inside one of them is worth an independent fire-test - a guard that never fires is indistinguishable from one that is inert, which is precisely feature 078's subject.
