Run 20260819T104500Z-41b3 (scheduler feature-supply root cause) was authored on a peer host with its method frozen and 14 blind-codex adjudications recorded, then pushed. Its execution phase could not run here for two independent reasons. (1) Its S1 slice cites .specify/3rtask/evidence/ops-*.jsonl, which .gitignore:170 excludes, so the corpus never propagates with the manifest that depends on it. (2) Every other source is an ABSOLUTE drive-letter path rooted at I:/coop/glpnet, and I: does not exist on this host; the same tree is D:/coop/glpnet here. So a manifest is only runnable on the machine that wrote it. Compounding it, 3rtask has no supported re-brief after a manifest revision within a run, so the only honest recovery is to mint a NEW run rather than edit the frozen, hashed blind inputs. Suggested fix: manifests should cite roots by logical NAME resolved per host (as the scheduler does with sched_root), and a run should be able to declare a reproducible corpus-projection recipe rather than depend on gitignored derived files.
