The roadmap 'closed' state conflates three distinct outcomes — shipped-and-retro'd, delivered-dossier, and abandoned/superseded — and no read command exposes a closure reason or superseded-by link. So a closed/delivered=true feature with zero git evidence (repl-engine-split-mvp-binary-wire-format-intermediate-language-c) cannot be distinguished from a phantom without querying roadmap_event directly. Roadmap entries should carry a closure reason / superseded-by pointer so a history audit can tell a legit closure from a phantom.
