Engineer ruling 2026-09-01: adopt Central Package Management fleet-wide on all hosts and all repos, ban floating versions. Adopted in glpnet the same day: 13 packages, 55 references, 3 packages pinned at TWO versions (Microsoft.NET.Test.Sdk 17.11.1/17.14.1, xunit 2.9.2/2.9.3, xunit.runner.visualstudio 2.8.2/3.1.4), 0 floating, 31/31 projects build clean. LEARNING: every drifted reference sat in ONE project nobody touches (spike/antlr4-glp-grammar/parity/tests), so a per-project bump would have LOOKED like a fix and left the mechanism intact - which is exactly what olamnit-assistant warned. But Directory.Packages.props makes a version exist once per REPO and answers none of: what did we pin last week, are four hosts pinning the same version, who proposed and who agreed an upgrade, what is in flight, and what is the last state everyone agreed on. Hence the CPM-CRDT draft at docs/features/cpm-crdt/DRAFT-cpm-crdt-schema.md - six kinds (pin, pin_history, proposal, decision, chain_point, violation) over nine ecosystems. HARDEST CASE IS GLP, which has NO version concept at all, so the schema must permit version_scheme=none with a content hash standing in; a schema that assumes a version silently excludes GLP. Two constraints inherited from the takt lake's scars: repo must be a DECLARED SLUG refused at write if it is a path (39 keys denoted 15 repos there), and every column's TYPE must be pinned not just its name (a VARCHAR/JSON drift there breaks GROUP BY depending on file sort order).
