buildkit-roadmap edit-feature accepts the notes body ONLY as --notes NOTES on the command line - there is no --notes-file and no stdin. Every edit resends the WHOLE body, so a roadmap notes field can never exceed the OS command-line cap (Windows CreateProcess: 32767 chars). Measured today: scheduler-pipeline-dispatch-superset notes reached 30163 chars and the next append failed with 'The filename or extension is too long' - about 2.6K from a PERMANENT ceiling after which no lane can append, correct or annotate that row at all. It bites hardest on exactly the rows that matter most, because those are the ones that accumulate analysis. Worse, my PowerShell loop branched on LASTEXITCODE which was stale from an earlier command, so the no-op reported 'APPLIED at expect-version=1' - a false green of exactly the class this row exists to fix, in my own tooling, on the day I documented the class. Two fixes: (1) add --notes-file PATH or accept - for stdin; (2) verify by CONTENT (does the marker appear in the re-read artifact) and NEVER by exit code - an exit code is a claim about a process, not evidence about an artifact.
