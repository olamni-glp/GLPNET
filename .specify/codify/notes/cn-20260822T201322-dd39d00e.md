BK-ONRESTART needs to become a configurable, per-host, auto-installable feature. Today the post-reboot fleet resume is a host-specific script invocation that each host reproduces by hand and gets wrong differently.

WHAT WORKS (ariellas mechanism, to be generalised): a Scheduled Task fires at logon with a ~45s delay and relaunches every repo lane as TABS in a Windows Terminal window, each resumed IN PLACE with `claude --continue` so the thread continues mid-conversation rather than being summarised. Verification is by counting processes, never by trusting the launcher message - a known failure mode is N tabs opening and running nothing.

WHAT IS MISSING and should be the feature:
1. PER-HOST WINDOW LAYOUT AS CONFIG. GAVRI/GAVRIELLAS wants TWO windows (window 1: ospark tefl hatzinor(ulpanit) olamnit buildkit qhstate yngraw research yngenios; window 2: crucible glpnet lejepa mstack yngwin/yngenios-windows). OLAMNIT, ARIELLAS and SHIRAS want ONE window with all lanes as tabs. Today that difference lives in a human's memory and a -Layout flag that defaults to the WRONG value (separate windows), so the correct invocation is the non-default one.
2. THE REPO LIST AS CONFIG, not as a hardcoded array in a script. Adding a repo to the fleet should not require editing a launcher.
3. REGISTER / UNREGISTER VERBS. `bk-onrestart register` from inside a repo adds that lane to this host's list; `unregister` removes it. That makes the list self-maintaining and auto-captured rather than curated.
4. AUTO-INSTALLABLE TRIGGER ON ANY HOST. One idempotent command installs (or removes) the at-logon Scheduled Task with the host's chosen layout and delay. Today only one host has it.
5. A HONEST VERIFICATION RECEIPT. The launcher must report how many lanes it actually STARTED versus how many it was asked to start, and name the ones it could not. Counting processes by hand is the current workaround and it is exactly the "a check that never ran is indistinguishable from a check that passed" defect class this repo keeps hitting.
6. MOUNT-WAIT MUST BE LOUD. If a share (I:) is absent after the wait, every downstream tool silently reports an EMPTY BOARD at exit 0 rather than "I cannot see the board". The launcher is the right place to refuse loudly, because it is the only component that knows the mounts were not ready.

INTEGRATE INTO TOOLING: make this a first-class buildkit feature with a per-host config (layout: one-window | two-window, window groupings, delay, repo list), register/unregister verbs, an idempotent install/uninstall of the at-logon trigger, and a started-vs-requested receipt.
