The component charged with keeping the fleet leader alive is Running and answers nothing. On GAVRIELLA, Get-Service reports YngBroker and YngGuardian Running while both hold ZERO listening sockets, confirmed by netstat with a positive control; UDP 24601 is bound by no process here, which qualifies Q-OSP0907F-01's premise that 24601 already runs on all four hosts. The guardian additionally retries 127.0.0.1:5432 in a loop with a fresh source port each attempt while nothing listens there, and the broker holds an ESTABLISHED connection to the container address - the two services are configured against different database addresses and only one exists. This is the liveness directive's own thesis proven locally: process existence is not liveness. Also: before proposing iroh work, searching showed the implementation is already allocated to ynglin (spec 012, 34659 lines of Rust) and glpnet already holds only the C# sidecar seam - proposing to build iroh would have been the conflicting allocation the directive exists to prevent.
