MEASURED 2026-09-01 on D:/coop/_takt-lake (5340 parquet, duckdb 1.5.5). The engineer asked for an era takt board comparing the same repo across hosts. It cannot be served: kind=era DOES carry a repo column (so the earlier claim that no repo dimension exists is too strong), but the value stored is a host-local absolute path - D:\BSTDEV\research\GLP\GLPNET, D:\BSTDEV\research\glp\GLPNET and /mnt/biwin/D_DRIVE/BSTDEV/research/crucible/glp/GLPNET are all glpnet. A path is definitionally not comparable across hosts, so WHERE repo='glpnet' returns ZERO rows. Normalising to the last path segment lowercased collapses 39 distinct keys to 15 real repos: 24 of 39 (62 percent) are re-spellings. yngenios alone has SIX spellings. Second finding: kind=era is 843 rows of which only 16 (1.9 percent) are measurable, and glpnet's own 38 rows across 3 spellings are 0 measurable - there is no glpnet era takt at all, which must be reported as NO DATA and never as 0.0h. Third finding: the reason column's TYPE drifts VARCHAR vs JSON between files, so a plain GROUP BY reason fails outright depending on which file sorts first. Remedy: repo must be a declared slug from a closed registry and a writer passing an absolute path must be REFUSED AT WRITE, exactly as an undeclared kind is; otherwise adding a repo= partition key just moves the 39-way split into a directory name. Contributed to the shared design at docs/features/era-takt-cross-repo-cross-host/DESIGN.crdt.md section 10.
