Mirroring four adjudicated decisions into the active marathon run, three of four 'buildkit-3rtask trace' calls returned {"ok": true, "routed": false, "reason": "marathon_error"} because another buildkit session held pgdb/.lock. Exit status was 0 and the top-level field said ok:true. A caller checking the exit code or the ok field would record four traces as written when only one was. Retried individually and all three then routed (trace_id 457/458/459). This is the same shape as the roadmap sync round that printed 'coop mirror skipped' while the inbox demonstrably resolved, and the same shape as this feature 078's own subject: a leg that did not run must not report as one that did. Recommend: routed:false must drive a non-zero exit or at minimum ok:false. Separately, buildkit auto-reaped orphaned PGlite bridges four times during this one session (PIDs 21060, 2740, 2908, plus a busy-registry refusal on PID 1548/2192/25696) on the dead-PID heuristic that ariellas SAFETY-20260817T211500Z warns is unsafe.
