fallback_used=True from buildkit-scheduler was read fleet-wide as proof the --root was not honoured, and that reading was written into COOP/ROOT.md as a hard-error rule. It is WRONG: substrate_io.py lines 20-22 say the flag reports which READER IMPLEMENTATION was used, and sched.substrate can never import because Python's stdlib 'sched' module shadows it (ModuleNotFoundError: 'sched' is not a package). The flag is therefore permanently True on every host with a stdlib Python - it carries no information about the board at all, and the rule would have marked every correct scheduler run on every host as failed. INTEGRATE INTO TOOLING: rename the surface to reader_impl=stdlib-fallback, or drop it from status/doctor human output entirely; the root check is the 'root ... exists=True' line and nothing else.
