Measured on D:/coop/glpnet/sched: all 26 allocate ops carry engineer_id=unassigned, proposed_actor=unassigned, workstation_id=null, from_state=null, to_state=null. Independently corroborated from source by a blind builder: allocator.allocate returns a view_envelope and writes no persisted assignment (orphan read); the write happens in allocate_writer.write_allocation, which records an assignee but never a state transition. Eligibility is state=='ready' (dispatch.py:210), reachable ONLY via an explicit transition op, and claim is state-neutral (from_state/to_state/e_t_s have no reachable reader). So allocating and claiming both leave a packet ineligible. Improvement: allocate must either propose a real actor or refuse loudly, and a packet with an allocation must not be able to sit in backlog silently.
