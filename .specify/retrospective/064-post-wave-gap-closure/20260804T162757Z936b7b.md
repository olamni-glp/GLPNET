### fleet-tooling
- [systematic] **The version-controlled roadmap import-manifest conflicts on every multi-host ship — third occurrence**
  - .specify/roadmap-sync/.import-manifest.json is a machine-generated mirror of the PGlite catalog, yet it is tracked in git, so any two hosts syncing the roadmap collide on it. It blocked this ship at the feature-PR merge (PR #130 CONFLICTING) and has now happened at least three times (b5998681, 7e1c055e, 0d2739b1). The repair is always the same mechanical rebuild (import --rebuild-manifest). Fix: either gitignore the mirror (the catalog is the authority and the manifest is derivable) or give it a merge driver that runs the rebuild automatically.
  - evidence: commit → `0d2739b1`
  - evidence: commit → `b5998681`

### review-process
- [systematic] **2 of 11 review fixes introduced new defects — only the separate post-fix adversarial pass caught them**
  - In T040 the fixers verified their own work and reported green. The cycle-3 verification pass (a reviewer distinct from both the cycle-2 reviewers and the fixers) found that the accept-error fix latched a transient econnaborted into a permanently dead listener and busy-spun the BE at 100 percent CPU, and that the bind-gate fix awaited one object but tested another, so a bind failure could still serve bridgeless instead of exiting 7. Fix: make the post-fix adversarial verification pass a MANDATORY cycle in /bk-codexreview fix mode, not an optional extra cycle - a fixer's own green run is not evidence that the finding closed.
  - evidence: file → `specs/064-post-wave-gap-closure/t040-codexreview.md`
  - evidence: commit → `5cce0109`
- [one_off] **The repo mandatory-reading gate silently zeroed the non-interactive codex planner**
  - codex exec obeyed AGENTS.md/CLAUDE.md 'STOP AND WAIT after the mandatory reading' and returned an empty plan with zero items, which would have degraded the review to a single-team plan (plan-merge refuses single_plan). It needed an explicit direction preamble stating the reading gate was satisfied and that the task itself is the direction. Fix: /bk-codexreview should prepend that preamble to every non-interactive codex invocation in repos that carry a start-of-session stop rule.
  - evidence: file → `reviews/064-post-wave-gap-closure/20260803T214953Z/cycle01/plan-prompt2.txt`

### toolchain
- [systematic] **glp_gleam/build is single-OTP: WSL and Windows runs collide and the failure masquerades as a code regression**
  - The WSL suite (gleam test, OTP 25) and the Windows Section I cross-runtime harness (gleam run under the Windows Erlang) share one build/ dir. Whichever ran last owns it; the other fails at beam load. In this cycle that cost a full suite re-run and produced a 546/547 that looked like a regression but was an artifact collision. Documented in CLAUDE.md this cycle (serial runs + rm -rf build between). A real fix is per-toolchain build dirs or a wrapper that keys build/ by OTP version.
  - evidence: file → `CLAUDE.md`
