## Root-cause findings

### ungrouped
- [systematic] **Hand-written LEB128 varint parser silently accepted overlong/overflow 10-group encodings**
  - ReadU64's shift>63 guard let the 10th (shift=63) group through, so bits 1-6 shifted past bit 63 and vanished — distinct/overlong byte strings decoded to the same u64 and a corrupt varint was accepted instead of loud-failing (canonical-determinism + FR-005 hole). The 253-green unit suite never exercised the 10-group (bit-63) path so it passed; caught only by the pre-ship plan-first review. Fixed + regression-tested. Lesson: hand-rolled codec primitives need explicit boundary/adversarial vectors (near-overflow, overlong, truncation), not just happy-path round-trips — consider a property/fuzz harness for the shared varint/TLV parser.
  - evidence: file → `csharp/glp_crdtmsg/envelope/VarInt.cs`
  - evidence: commit → `dcc9f6c9`
- [one_off] **NUL bytes substituted for spaces in a source string literal during file authoring (compiled + tested green, latent)**
  - Macaroon.cs Caveat.Bytes() carried \x00 where spaces were intended in an interpolated string; NUL is valid in a C# string literal so it compiled and all tests passed (sign/verify used identical bytes). Detected by the review's byte scan; field rewritten length-prefixed (also fixing an injectivity nit). Lesson: a cheap NUL-byte scan over authored source catches this class of silent authoring artifact.
  - evidence: file → `csharp/glp_crdtmsg/cap/Macaroon.cs`
