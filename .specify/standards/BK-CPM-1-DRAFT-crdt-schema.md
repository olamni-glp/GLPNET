## 1 · Why a CRDT at all — the problem being solved

Ruling `Q-shiras-36` adopted CPM because a per-project version bump *"fixes 27 refs and
leaves the drift mechanism intact"*. The same is true one level up: adopting
`Directory.Packages.props` in each repo, one repo at a time, fixes today's drift **within**
a repo and leaves the *fleet* drift mechanism intact. Four hosts × a dozen repos × ten
ecosystems, each edited by a different lane, with no shared record, reproduces the identical
failure at fleet scale.

What is needed is a record that:

- **converges without coordination** — hosts are frequently offline from each other (the
  coop volume is explicitly asynchronous and "not always mounted on both at once");
- **never loses a writer's statement** — no lane's record may be silently overwritten;
- **is verifiable and archivable** — you can prove what the fleet's pins were on a date;
- **spans ecosystems** — one mechanism for .NET, Python, JS/TS, Dart, Go, Rust, C/C++, GLP.

## 2 · Substrate — REUSE the proven one, do not invent

**Proposal: the same Hive-partitioned append-only parquet store the takt lake already uses.**

```
<coop-root>/_cpm-lake/cpm/kind=<k>/host=<h>/date=<YYYY-MM-DD>/<actor>-<ts>-<n>.parquet
```

Rationale, measured rather than assumed: that substrate already carries **5,167 rows across
four hosts** and converges with no coordination, because **every writer owns its own
partition and never writes another writer's**. It is a G-Set of immutable records — the
simplest CRDT that exists, and the one hardest to get wrong.

**Three defects were MEASURED in that lake on 2026-09-01, and BK-CPM-1 fixes each by
construction rather than inheriting it:**

| # | measured defect in the takt lake | BK-CPM-1 fix |
|---|---|---|
| D1 | Same column, different parquet type across hosts (`repo` is JSON on ariellas, VARCHAR elsewhere) — one file aborts a whole-kind scan | **§4 declares an explicit typed schema per kind; every writer MUST emit exactly these types.** Readers additionally cast defensively. |
| D2 | `repo` is written as an absolute host-specific path, so GLPNET is three different identities (`/mnt/.../crucible/glp/GLPNET`, `D:\BSTDEV\research\GLP\GLPNET`, `D:\BSTDEV\research\glp\GLPNET`) — cross-host comparison of one repo is impossible | **`repo_id` is a stable slug, never a path.** `repo_path` is retained as observational metadata only and is never an identity. |
| D3 | Two names for one kind (`kind=token` 17 rows beside `kind=tokens` 658) — reading one under-reports, reading both without dedup double-counts | **Kind names are CLOSED (§4).** A reader MUST reject an unknown kind loudly rather than ignore it. |

## 3 · Identity and ordering — the two rules everything else rests on

**R1 — Identity is `record_id` (UUIDv7).** Time-ordered, globally unique, generated by the
writer. The same logical record may legitimately appear in more than one file (a local write
plus a fleet sync of it); dedup is by `record_id`, never by file or row position.

**R2 — The order is a Hybrid Logical Clock, and it is TOTAL.**

```
hlc = (physical_ms BIGINT, logical BIGINT, actor_id VARCHAR)
compare lexicographically; actor_id breaks the final tie
```

Wall-clock alone is **not** acceptable, and this is measured, not theoretical: `scheduler
doctor` on this fleet reports *"heartbeat 664589s AHEAD of any work"* and
*"skew-exceeds-threshold"* for 7 of 9 actors. A last-writer-wins register ordered on wall
clock would let a skewed host silently win every conflict. Including `actor_id` makes the
order **total**, which is what guarantees every host folds identical bytes into an identical
state — the property a non-total order quietly destroys.

## 4 · The five kinds

### 4.1 `kind=pin` — current state (LWW-Register per coordinate)

The declared version of one package, for one repo, in one ecosystem.

| column | type | notes |
|---|---|---|
| `record_id` | VARCHAR | UUIDv7 (R1) |
| `hlc_physical_ms` / `hlc_logical` / `actor_id` | BIGINT / BIGINT / VARCHAR | R2 |
| `repo_id` | VARCHAR | **stable slug, never a path** (D2) |
| `repo_path` | VARCHAR | observational only, never an identity |
| `host` | VARCHAR | partition column |
| `ecosystem` | VARCHAR | §5 closed enum |
| `package_id` | VARCHAR | canonicalised per §5 |
| `version` | VARCHAR | as declared |
| `constraint_kind` | VARCHAR | `exact` \| `range` \| `floating` \| `vendored` |
| `manifest_path` | VARCHAR | repo-relative, e.g. `Directory.Packages.props` |
| `is_central` | BOOLEAN | true when declared in the repo's ONE central manifest |
| `policy_violation` | VARCHAR | `''`, `floating_banned`, `decentralised`, `drift` |
| `state_hash` | VARCHAR | sha256 of the canonical tuple, for §4.5 |

**Merge:** LWW per `(repo_id, ecosystem, package_id)` on the R2 order. A *coordinate* has
exactly one live pin; a repo's full state is the set of live pins.

🔴 **`constraint_kind='floating'` is recorded, never suppressed.** Ruling `Q-shiras-36` bans
floating versions precisely because `10.*` *"silently follows the 10 line and will never move
to 11 on its own"* — a defect no bump can fix. A schema that refuses to store the violation
cannot report it. **The ban is enforced by reporting, not by data loss.**

### 4.2 `kind=proposal` — proposed upgrades (Add-wins set)

| column | type | notes |
|---|---|---|
| `record_id`, `hlc_*`, `actor_id` | — | R1/R2 |
| `proposal_id` | VARCHAR | stable across its lifetime |
| `scope` | VARCHAR | `fleet` \| `repo:<repo_id>` \| `ecosystem:<eco>` |
| `ecosystem`, `package_id` | VARCHAR | the coordinate |
| `from_version`, `to_version` | VARCHAR | `from_version` may be `*` for fleet-wide |
| `rationale` | VARCHAR | why |
| `evidence` | VARCHAR | CVE, EOL notice, build log — **required for `security` class** |
| `class` | VARCHAR | `security` \| `eol` \| `feature` \| `drift-resolution` \| `framework` |
| `required_ackers` | VARCHAR | JSON array of actor_ids whose ACK unanimity requires |

**Merge:** add-wins. A proposal is never deleted; it is superseded (§4.3). Add-wins is the
correct bias here — losing a proposed security upgrade because of a merge race is strictly
worse than carrying a redundant one.

### 4.3 `kind=vote` — ACK / NACK (LWW-Register per (proposal, actor))

| column | notes |
|---|---|
| `proposal_id`, `actor_id` | the register key |
| `verdict` | `ack` \| `nack` \| `abstain` \| `superseded-by:<proposal_id>` |
| `reason` | required for `nack` — a bare NACK is not a vote |
| `hlc_*` | R2 |

**Merge:** an actor's latest verdict wins. An actor may change its mind; the fleet sees only
the latest. **Unanimity** = every `required_ackers` entry has a live verdict of `ack`.
Silence is **never** consent — an actor with no row is `pending`, reported as such, and
`pending ≠ abstain`.

### 4.4 `kind=apply` — what was actually done (append-only event log)

| column | notes |
|---|---|
| `proposal_id` | the agreed proposal, or `''` for an unproposed direct edit |
| `repo_id`, `ecosystem`, `package_id`, `from_version`, `to_version` | — |
| `commit_sha` | the commit that carried it |
| `build_evidence` | the command **and its result** |
| `outcome` | `applied` \| `reverted` \| `failed` |

🔴 **`build_evidence` is mandatory and is a command plus its result — never "it builds".**
This fleet has already recorded that *a cancelled CI job reported "0 failures" and hid two
failing suites for days*. The same discipline that governs an ACK-2 governs an apply row.

### 4.5 `kind=chain` — archiving / chaining points (the verifiable checkpoint)

| column | notes |
|---|---|
| `chain_id` | UUIDv7 |
| `prev_chain_hash` | previous checkpoint's `chain_hash` — forms the chain |
| `scope` | `fleet` \| `repo:<repo_id>` |
| `covered_watermark` | the HLC below which this checkpoint is complete |
| `pin_set_hash` | sha256 over the canonically-sorted live `state_hash` set |
| `pin_count` | rows covered |
| `chain_hash` | sha256(`prev_chain_hash` ‖ `pin_set_hash` ‖ `covered_watermark` ‖ `scope`) |

A checkpoint answers *"what were the fleet's pins on this date, and can you prove it?"*, and
gives a safe **archival** boundary: op-log files entirely below a checkpoint's watermark may
be moved to cold storage.

🔴 **Checkpoints are ADVISORY, never authoritative.** The op log remains the source of truth.
A checkpoint that disagrees with a replay of the log is *itself* the defect and must be
reported, never trusted over the log. This preserves the CRDT property: a checkpoint is a
cache, and a late-arriving record from a partitioned host is still merged normally.

## 5 · The ecosystem superset — .NET first, all ten covered

The schema is ecosystem-agnostic; only this table is ecosystem-specific. Adding an ecosystem
is a row here, **never** a schema change.

| `ecosystem` | central manifest (preferred) | per-project manifest | version syntax | `package_id` canonical form |
|---|---|---|---|---|
| `dotnet` | `Directory.Packages.props` (`PackageVersion`) | `*.csproj` (`PackageReference`, no `Version`) | SemVer + `[range]` + floating `10.*` | case-insensitive; store as published |
| `python` | `pyproject.toml` `[project]` / `constraints.txt` / uv `[tool.uv]` | per-package `pyproject.toml` | PEP 440 | PEP 503 normalised (lowercase, `-`) |
| `javascript` | `package.json` `overrides` / pnpm `catalog:` | workspace `package.json` | SemVer ranges | lowercase, scope preserved (`@scope/name`) |
| `typescript` | same as `javascript` (one ecosystem, `@types/*` are ordinary packages) | — | — | — |
| `dart` | `pubspec.yaml` `dependency_overrides` / workspace `resolution` | per-package `pubspec.yaml` | caret `^1.2.3` | `lowercase_with_underscores` |
| `go` | `go.work` + `go.mod` `replace` | per-module `go.mod` | SemVer + pseudo-versions | **case-sensitive** module path, `!x` escaping |
| `rust` | `Cargo.toml` `[workspace.dependencies]` | crate `Cargo.toml` (`workspace = true`) | SemVer caret | `lowercase-with-hyphens` |
| `cpp` | `vcpkg.json` + `vcpkg-configuration.json` builtin-baseline | `conanfile.txt` / CMake `FetchContent` pinned to a tag/SHA | vcpkg baseline SHA / Conan ranges | lowercase |
| `c` | same as `cpp` (one toolchain surface in this fleet) | — | — | — |
| `glp` | 🔴 **none exists** — GLP has no package manager | `programs/self.glp` scope chain; `-module`/`imported procedure` | n/a | module name |

🔴 **GLP is the honest gap and MUST NOT be faked.** GLP has no package manager, and inventing
one would be a language-definition change requiring an express §1.14 ruling from Udi
(CLAUDE.md §1.14 / DISCIPLINE.md §1.14). BK-CPM-1 therefore records GLP dependencies as
`constraint_kind='vendored'` pins over the `self.glp` scope chain and cross-module
`imported procedure` declarations — an **observation**, not a package manager. `glpnet` is
**not** a separate ecosystem: it is a repo containing `dotnet`, `dart`, `javascript` and
`glp` ecosystems, which is exactly what `repo_id` × `ecosystem` is for.

## 6 · What the schema makes answerable

- "Show every floating version in the fleet" → `pin` where `constraint_kind='floating'`.
- "Which packages are pinned at two versions?" → `pin` grouped by coordinate, `count(DISTINCT version) > 1`.
- "Is upgrade X unanimously agreed?" → `vote` folded per `proposal_id` against `required_ackers`, with `pending` distinguished from `abstain`.
- "What were our pins on 2026-08-31, provably?" → nearest `chain` checkpoint + replay.
- "Which repos still have no central manifest?" → `pin` where `is_central = false`.
- "Did the agreed upgrade actually land, with proof?" → `apply` joined to `proposal`.

## 7 · Known costs, stated rather than hidden

1. **`repo_id` requires a fleet-agreed slug registry.** Without it D2 recurs in a new shape.
   Proposed seed: `glpnet`, `buildkit`, `qhstate`, `olamnit`, `yngenios`, `yngenios-windows`,
   `yngenios-linux`, `yngenios-app`, `mstack`, `ospark`, `tefl`, `hatzinor`, `lejepa`,
   `crucible`. **This list is part of what ACK-ers are agreeing to.**
2. **`ecosystem` is a closed enum by design.** Extending it is a schema-version bump with its
   own ACK round — deliberately, so a lane cannot invent a private ecosystem silently.
3. **Unanimity is expensive.** A `security`-class proposal blocked on one unreachable host is
   a real risk; §8 Q3 puts the break-glass rule to the fleet rather than deciding it here.
4. **No writer exists yet.** This is a schema, not an implementation. Nothing writes `_cpm-lake`
   until the pilot is agreed.

## 8 · 🔴 OPEN QUESTIONS the ACK round must settle

**Q1 — one lake or two?** Reuse the takt lake root with a `cpm/` prefix, or a separate
`_cpm-lake`? *Drafter's recommendation: separate root.* CPM retention is years; takt is
operational. Coupling them makes takt archival hostage to CPM's retention.

**Q2 — is `is_central=false` a violation or a state?** *Recommendation: a state, reported.*
Some ecosystems (C/C++ via FetchContent, GLP) have no central manifest, so treating it as a
violation would permanently mis-flag them.

**Q3 — break-glass for a `security`-class proposal when an ACKer is unreachable.**
*Recommendation: a `security` proposal auto-agrees after a declared timeout with the
non-responding actors recorded as `timed-out` — never silently as `ack`.* An unpatched CVE
waiting on an offline host is the worse failure. **This is the question most likely to divide
the fleet and is the one I least want to decide alone.**

**Q4 — does `repo_id` need a `product`/`org` prefix** for repos of the same name in different
estates? *Recommendation: not yet; add only when a collision is measured.*

## Contribution — gavriella / glpnet, 2026-09-01T16:30Z

This lane **withdrew its own competing draft** (`docs/features/cpm-crdt/DRAFT-cpm-crdt-schema.md`)
rather than add a seventh document to a fleet already forked seven ways. What follows is that
draft's measured content, contributed here instead.

### C-1 · GLP/GLPNET has NO version concept — MEASURED, and the obvious workarounds tested

Not assumed, and not merely "no `-version` directive". A red-team objected that version identity
might be encoded elsewhere; I tested exactly that:

| probe | result |
|---|---|
| module-level directives in any `.glp` source | only `-mode`, `-module`, `-export`, `-import` — **no `-version`** |
| "version" tokens in `.glp` sources | 64, **all incidental English in comments** ("the WxW-compliant version") |
| module names containing any digit | **3**; the one example is `play12` — an **ordinal**, not a version |
| `vN` / `_N_N` patterns in module names | **0** |
| version-like directory segments under `programs/` | **0** |

⇒ `version_scheme = "none"` with a **content hash** as the version stand-in must be
**first-class**, not an afterthought. A schema that presupposes a comparable version identifier
silently excludes GLP while reading as complete — and GLP is the hardest case precisely because
it fails quietly rather than loudly.

### C-2 · Six kinds, because a props file records the OUTCOME and never the DECISION

`Directory.Packages.props` makes a version exist once per repo. It cannot answer: what did we pin
last week; are four hosts pinning the same version; **who proposed this upgrade and who agreed
it**; what is in flight so two lanes do not both do it; and what is the last state everyone
agreed on. Hence: `pin`, `pin_history`, `proposal`, `decision`, `chain_point`, `violation`.
`pin_history` is separate from `pin` deliberately — a reader asking "what is pinned" must not
fold the whole history, and a reader auditing change must not guess which row is current.

### C-3 · Two constraints earned from the takt lake's scars — do not repeat them here

1. **`repo` must be a DECLARED SLUG, refused at write if it is a path.** In the takt lake the
   same field holds a host-local absolute path, so **39 keys denote 15 real repos** (62%
   re-spellings; `yngenios` alone has six) and `WHERE repo='glpnet'` returns **zero rows**.
   Inserting a `repo=` partition key without a write-time refusal merely moves the 39-way split
   from a column into a directory name, where it is far more expensive to undo.
2. **Pin every column's TYPE, not only its name.** Measured on three separate columns in the
   takt lake (`reason`, `total_tokens`, `repo`): the same column is JSON in some parquet files
   and VARCHAR in others. The failure is at **parquet schema unification — before any cast in
   the query can run** — so `kind=tokens` currently **cannot be read across hosts at all**.
   `union_by_name` reconciles names, never types.

### C-4 · glpnet's CPM adoption, as the pilot's first datapoint

13 packages · 55 references · **3 packages pinned at two versions** · **0 floating** ·
**31/31 projects build clean** under `Directory.Packages.props`. Every drifted reference sat in
**one project nobody touches**, which is the shape §7's drift query must surface: *drift
concentrates where nobody looks*, so a per-project bump looks like a fix and leaves the
mechanism intact.
