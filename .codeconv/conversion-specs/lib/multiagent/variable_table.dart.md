## Rationale and research provenance

### rf-dart-shared-mutable-record-by-reference-to-csharp-class -- the load-bearing reference-identity decision

- Deep analysis. `VariableEntry` is the per-cell suspension-and-bound-value anchor used by the core runtime to attach suspension lists to imported reader cells that don't have a local writer cell (per the file's leading doc-comment). Two of its fields (`boundValue`, `suspensions`) are mutated in place after construction; a third (`pairedReaderCreatorLocalId`) is set when the import pairing is finalised. The surrounding unification + suspension-management logic relies on every reference to a given entry observing the SAME `boundValue`, the SAME `suspensions` head, and the SAME `pairedReaderCreatorLocalId`. The Dart source enforces this by using `class` (Dart class instances are always reference types -- there is no `struct` in Dart), no `==`/`hashCode` override, and bare mutable fields (no privacy modifier on the mutable fields, so the runtime can read AND write them externally). The historical comment makes it clear that the full V_p table has been replaced by W_p (`GlobalWritersTable`); `VariableEntry` is now the residual per-cell anchor consumed by the suspension code. Its shared-by-reference-identity contract is symmetric with `SuspensionRecord`/`SuspensionListNode` in `lib/runtime/suspension.dart` (which form the same design unit: one record per goal, multiple wrapper nodes per record).

- Authoritative Dart. The Dart language tour (https://dart.dev/language/classes) is unambiguous: "Objects of a class are created using a constructor and stored on the heap; variables hold references to those objects." Combined with the file-level doc-comment and the surrounding W_p / suspension-management code, the shared-by-reference contract is documented at language, file, and design-unit levels.

- Authoritative .NET. The C# reference-types page (https://learn.microsoft.com/dotnet/csharp/language-reference/builtin-types/reference-types) states: "Variables of reference types store references to their data (objects), while variables of value types directly contain their data. With reference types, two variables can reference the same object; therefore, operations on one variable can affect the object referenced by the other variable." This is precisely the shared-bound-value-and-suspension-list contract the maGLP runtime relies on. The records page (https://learn.microsoft.com/dotnet/csharp/language-reference/builtin-types/record) states: "Records use value-based equality. Two record instances are equal if they're of the same type and store the same values." Two distinct `VariableEntry` instances with structurally identical fields represent distinct variable slots (e.g. two cells with the same `varId` in different agents) and MUST NOT compare equal -- `record class` is therefore rejected on documented grounds. The structs page (https://learn.microsoft.com/dotnet/csharp/language-reference/builtin-types/struct) states: "Structure types have value semantics. That is, a variable of a structure type contains an instance of the type." `struct`/`record struct` would copy on every field read and every assignment; binding a variable through one entry reference would leave other references' copies still unbound. Categorically rejected.

- Decision. (i) `VariableEntry` -> .NET `class` (reference type), NOT `record class` / `struct` / `record struct`. (ii) Final Dart fields (`varId`, `isReader`, `creator`, `creatorLocalId`) -> get-only auto-properties (`{ get; }`) assigned in the constructor. (iii) Mutable Dart fields (`boundValue`, `suspensions`, `pairedReaderCreatorLocalId`) -> properties with public setter (`{ get; set; }`), NOT `{ get; private set; }` and NOT `init`-only -- the runtime mutates these externally. (iv) No `==`/`Equals`/`GetHashCode` override -- default reference equality preserved. (v) Concurrency-model invariant (single-owning-thread per agent) inherited from `GlobalWritersTable`: no `lock`, no `Interlocked`, no `volatile`, no concurrent collections, no async signature on any member; the .NET port of `isolate_manager.dart` is responsible for providing the actor-mailbox / pinned-thread / single-threaded-scheduler equivalent of the Dart isolate boundary. Fully decided from official Dart and .NET documentation on both sides; no escalation needed.

### rf-dart-string-interpolation-conditional-suffix-to-csharp-interpolation -- diagnostic-output preservation

- Deep analysis. The `toString()` override is the load-bearing trace string for the entry. The Dart shape uses `${}` interpolation, a conditional ternary to pick `R$varId?` vs `W$varId`, and a conditional ternary to add `, creatorLocalId=$creatorLocalId` only when `creatorLocalId != varId`. The trailing literal `?` on the R-key is the maGLP/FCP convention (R-keys are written with a `?` to denote 'reader view', W-keys without -- documented in the maGLP-spec and consumed verbatim by REPL `:trace` output and integration-test fixtures).

- Authoritative .NET. The interpolated-strings reference (https://learn.microsoft.com/dotnet/csharp/language-reference/tokens/interpolated) describes `$"..."` interpolation as the structural counterpart of Dart `'...'` interpolation: every interpolated expression is converted to a string via the formatter (calling `IFormattable.ToString` or `object.ToString()`). For non-nullable arguments (`VarId`, `IsReader`, `Creator`, `CreatorLocalId` are all non-nullable) the interpolation produces the expected text without the `?.ToString() ?? "null"` workaround needed in `SuspensionRecord.ToString()`. The ternary operator (https://learn.microsoft.com/dotnet/csharp/language-reference/operators/conditional-operator) handles the conditional key prefix and conditional suffix directly.

- Decision. Two local `string` variables computed via ternary, then a single interpolated return. NO `StringBuilder` (over-translation; the format is fixed-shape, not loop-driven). The `R{VarId}?` / `W{VarId}` shapes and the conditional `, creatorLocalId={CreatorLocalId}` suffix are preserved verbatim. Authoritative; no escalation.

## Notes

- The shared-mutable-by-reference contract is the load-bearing maGLP / FCP idiom for cell suspension and bound-value caching. Every translation choice in this file (class-not-record-not-struct, public-setter on mutable properties, get-only on `final` fields, `?? VarId` fallback in the constructor body) is in service of preserving that contract. Erasing any one of them silently breaks the contract.

- The named-constructor-default-from-other-parameter pattern (`creatorLocalId ?? varId` in the initialiser list) is a Dart idiom that does NOT translate to a .NET optional-parameter default (which must be a compile-time constant). The translation makes the parameter nullable with a compile-time `null` default and computes the fallback in the constructor body -- the only faithful .NET shape. This is documented here once and is intended to apply uniformly to every other Dart constructor in the codebase that uses `?? <other-param>` in its initialiser list.

- The `R<varId>?` trailing-`?` literal in the key string is NOT a nullable-type marker; it is the maGLP convention for marking reader-view keys. The .NET interpolation preserves the literal character verbatim.

- Concurrency model: inherited from `GlobalWritersTable` (per-agent single-owning-thread, NO `ConcurrentDictionary`, NO `Interlocked`, NO `lock`). `VariableEntry` instances are owned by the same isolate as their containing `MadContext` / W_p and are touched only from that isolate's owning execution context in the .NET port.

- Async/Stream/Future/Completer/Mixin/Sealed/Isolate nuances are ABSENT from this file -- correctly not asserted. The entry is purely synchronous in-memory state.

- Zero escalations. Every non-trivial construct is grounded in official Dart and/or .NET documentation. The value-vs-reference decision, the property-shape decisions, the null-safety decisions, the constructor-default-fallback decision, the import-to-using decision, the library-elision decision, and the interpolation-preservation decision are all authoritatively decidable; no `kind: undecidable` here.
