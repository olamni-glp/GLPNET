## Notes

- **Per-agent single-owning-thread invariant.** `AgentRuntime` is the per-agent FACADE — all state reachable through it (`_runtime`, `_ctx`, `_scheduler`, `_userInput`, `_netInput`, and through `_ctx` into `Wp`/`Mp`/`GlobalSendRegistry`/`_serializer`/the runtime heap and goal queue) is per-instance and isolate-local. The invariant recorded once on `GlobalWritersTable.dart.md` is INHERITED here and across the multiagent family. No `lock`, no `SemaphoreSlim`, no `ConcurrentDictionary`, no `Interlocked` inside `AgentRuntime` methods — the atomicity for compound check-then-act sequences (init pipeline, message-dispatch, drain-then-flush) is end-to-end at the isolate-ownership level, enforced by the `isolate_manager.dart` port (whose threading model — pinned Thread / single-threaded TaskScheduler / actor mailbox via Channel<T> / synchronisation-context binding — is deferred to that file's convspec).

- **Dual library aliases (`ast` / `rt`).** This file is the FIRST in the corpus to use Dart library prefix aliases. Codegen MUST emit two `using` alias directives (`using ast = ...; using rt = ...;`) to preserve the type-disambiguation the Dart aliases provide. Failing to preserve them would cause a name-collision compile error in C# (two `Term` types in scope).

- **`async void` lambda on void-typed delegate.** The `OnMessageReady` assignment INSIDE `Initialize` is the canonical fire-and-forget pattern for an event-handler-style callback. Codegen MUST emit `async (...) => { ... await ...; }` with the implicit async-void lambda conversion — preserving the Dart fire-and-forget semantic. The exception-cannot-be-caught caveat is INHERITED from Dart and authoritative-grounded in Microsoft Learn 'async (C# Reference)'.

- **Async method `Async` suffix convention.** Every method in this file that returns `Future<T>` maps to a C# method returning `Task<T>` AND named with the `Async` suffix per Microsoft FrameworkDesignGuidelines. Six methods affected: `Initialize` → `InitializeAsync`, `InjectUserInput` → `InjectUserInputAsync`, `OnMadMessageReceived` → `OnMadMessageReceivedAsync`, `OnLegacyMessageReceived` → `OnLegacyMessageReceivedAsync`, `_SendMadPayload` → `_SendMadPayloadAsync`, `RunUntilQuiescent` → `RunUntilQuiescentAsync`, `_RunUntilQuiescent` → `_RunUntilQuiescentAsync`. The public ones become breaking changes for callers — coordinated update with the coordinator port required.

- **Culture-insensitive case conversion.** Every Dart `.toUpperCase()` / `.toLowerCase()` maps to C# `.ToUpperInvariant()` / `.ToLowerInvariant()` (Microsoft Learn recommendation for non-display use). NOT culture-sensitive `.ToUpper()` / `.ToLower()`. Affects `_Tag`, multiple `agentId.toLowerCase()` sites, `friends.first.toLowerCase()`, `from.toLowerCase()`, `agentId.toLowerCase()` in PayloadSerializer construction.

- **`Uint8List` → `byte[]`.** Used in three method signatures (`OnSendMadMessage` field type, `OnMadMessageReceivedAsync` parameter, `_SendMadPayloadAsync` parameter). NOT `ReadOnlyMemory<byte>` (would break the `payload_serializer.dart` convspec's pinned `List<byte>`/`byte[]` payload type contract). Authoritative.

- **`dynamic` → `object?`.** The `OnLegacyMessageReceivedAsync` parameter type is `dynamic` in Dart; the C# faithful counterpart is `object?` (NOT C# `dynamic`, which incurs DLR overhead unnecessary here — no method dispatch on the payload).

- **`int.tryParse` null-or-string fallback.** The `ExtraArgs` parsing loop tries to parse each extra arg as `int` and falls back to the original string if parse fails. The Dart shape `int.tryParse(extra) ?? extra` returns `Object?` polymorphically; the C# shape requires an explicit `(object?)intVal ?? extra` cast to type-check (C# `??` requires same-type operands).

- **`await null` is a no-op in Dart but throws NRE in C#.** The `_SendMadPayloadAsync` body uses an explicit local-capture + null-check + await pattern (NOT `await cb?.Invoke(...)`, which would throw NRE when `cb` is null). LOAD-BEARING decision.

- **Async-without-await in `_RunUntilQuiescentAsync`.** The body contains no `await` expressions but the method is declared `async`. Codegen MAY keep the `async` keyword (one state-machine allocation per call but Dart shape fidelity) OR drop `async` and use `Task.FromResult` at each return point (zero state machine but obscures shape). Recorded preference: keep `async`.
