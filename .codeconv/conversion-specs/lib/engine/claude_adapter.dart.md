### rf-dart-const-ctor-vs-csharp-default-ctor -- const constructor on an empty placeholder class

- Deep analysis. The only behaviour the constructor can have is identity: Dart `const` constructors create compile-time-canonical instances, so two `const ClaudeEngineAdapter()` expressions in the same compilation are guaranteed to refer to the same object. Since the class has zero state, the canonicalisation is observable only via reference identity (`identical(a, b) == true`). The class is a documented skeleton/placeholder with no methods to override and no fields to initialise, so the conversion's only obligations are (i) preserve the type's existence and name, (ii) preserve top-level (library-public) visibility, (iii) preserve the doc-comment provenance, and (iv) be honest about the `const` semantic gap.

## Notes

- Dart `export` versus .NET namespaces -- nuance addressed even though this file contains no `export` directive. The brief flagged a possibility that `claude_adapter.dart` might be a pure re-export stub; on inspection it is not -- it is a placeholder type definition. The general nuance, recorded once here for downstream consistency: Dart `export 'src/x.dart';` re-publishes another library's public identifiers as part of the current library's surface, so a downstream `import 'package:foo/foo.dart'` transitively sees the re-exported names. .NET has no symmetrical mechanism: a .NET file cannot re-export types from a namespace under a different namespace name. The faithful translation of a Dart `export`-only stub is therefore NOT a type or file of its own but a `using`-style namespace alias in each consuming file (or, for assembly-level re-bundling, the consuming project adding the appropriate assembly reference). Translators of any export-only Dart file should record this in that file's spec as a one-line note ("no target file emitted; consumers add a namespace alias to the underlying namespace") rather than emitting an empty .NET file that pretends to re-export.

- Const-instance use-site nuance (recorded so downstream specs are coherent with this one). Dart `const ClaudeEngineAdapter()` literals are compile-time canonical; the per-callsite translation choice is (a) a `static readonly` singleton field initialised once if the original call site is itself inside a compile-time-constant Dart context (e.g. another `const` expression, a `const` field initialiser), or (b) a fresh runtime instance via `new` if it isn't.
