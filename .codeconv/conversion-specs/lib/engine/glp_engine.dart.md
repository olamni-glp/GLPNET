# Conversion Spec — lib/engine/glp_engine.dart

> Conversion-spec artifact for lib/engine/glp_engine.dart (FR-011).
> Spec-only (FR-023): describes the Dart->C# conversion; contains NO
> compilable C#. A later codegen stage consumes the structured block.
>
> `GlpEngine` is the **embeddable execution core** for running GLP
> programs — the ONE way to compile-typecheck-load-run a `.glp`
> program (REPL, `IsolateManager` for madGLP agent isolates, tests).
> It owns a `GlpCompiler` + `GlpRuntime` pair, holds two parallel
> registries — `_loadedPrograms` (raw bytecode by source name) and
> `_loadedModules` (module-info by module name) — plus pre-compiled
> `serve/2` bytecode for dynamic dispatch, two embedded `.glp` source
> string constants (the `_serveSource` and `_madPredicatesSource`),
> a `MadContext?` injection seam for madGLP mode, and a single
> Dart-async drain entry point (`runGoal` → `Future<ExecutionResult>`).
>

### rf-dart-library-directive-to-csharp-namespace-no-counterpart — `library;` directive elided

Reused verbatim from `lib/runtime/heap_fcp.dart.md` / `lib/multiagent/mad_context.dart.md` / `lib/engine/claude_adapter.dart.md`. Authoritative; no escalation.

### rf-dart-aliased-import-to-csharp-per-symbol-using-alias — `as rt;` runtime-terms prefix-aliased import

- Deep analysis. The Dart source declares `import 'package:glp_runtime/runtime/terms.dart' as rt;` — a Dart prefix-aliased import that makes every public symbol of `terms.dart` accessible under the `rt.` prefix. THE LOAD-BEARING import: AST `Term`/`VarTerm`/`ConstTerm`/`ListTerm`/`StructTerm` (from `ast.dart`) and runtime `Term`/`VarRef`/`ConstTerm`/`StructTerm` (from `runtime/terms.dart`) are simultaneously in scope inside `_setupArgument` and the term-builder methods; the `rt.` prefix disambiguates.
- Authoritative Dart. https://dart.dev/language/libraries#specifying-a-library-prefix — Dart `import '...' as P;` makes every public symbol accessible as `P.Symbol`; canonical disambiguation idiom when libraries have overlapping type names.
- Authoritative .NET. https://learn.microsoft.com/dotnet/csharp/language-reference/keywords/using-directive — C# `using` directives do NOT provide a comparable namespace-prefix mechanism. Two analogues: (i) namespace alias `using P = Namespace;` (closest semantic match but applies to a whole namespace); (ii) per-symbol type alias `using P = Namespace.Type;` (introduces one alias per type).
- Decision. Per-symbol type aliases (option ii). The collision is between four AST types and four runtime types; per-symbol aliases avoid polluting all non-colliding references with an unnecessary prefix. Codegen emits `using RtTerm = ...Runtime.Term; using RtVarRef = ...Runtime.VarRef; using RtConstTerm = ...Runtime.ConstTerm; using RtStructTerm = ...Runtime.StructTerm;`. Authoritative; no escalation.

### rf-dart-raw-string-triple-quote-to-csharp-verbatim-or-raw-string-literal — embedded `.glp` source constants

- Deep analysis. Two top-level `const String` constants (`_serveSource`, `_madPredicatesSource`) use Dart's `r'''...'''` raw triple-quote literal. They hold embedded `.glp` source that the `GlpCompiler` lexer parses byte-for-byte.
- Authoritative Dart. https://dart.dev/language/built-in-types#strings — raw strings prefixed with `r` treat backslashes and `$` as literal characters; triple-quote strings preserve embedded newlines.
- Authoritative .NET. https://learn.microsoft.com/dotnet/csharp/programming-guide/strings/ — verbatim strings `@"..."` preserve backslashes literally; embedded `"` requires `""` doubling. C# 11.0+ raw-string-literals `"""..."""` (https://learn.microsoft.com/dotnet/csharp/language-reference/tokens/raw-string) preserve everything verbatim including `"` without doubling.
- Decision. Either C# verbatim `@"..."` (universal) or C# 11.0+ raw-string-literal `"""..."""`. Both byte-identical content. Codegen target version determines which. Authoritative; no escalation.
