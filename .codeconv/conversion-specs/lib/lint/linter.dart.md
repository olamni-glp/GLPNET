## Rationale and research provenance (per non-trivial construct)

### rf-dart-import-relative-to-csharp-using-namespace — package imports (FR-024 cache hit)

- Deep analysis: both imports are intra-project (`package:glp_runtime/bytecode/...`), pulling in the Op class hierarchy plus BytecodeProgram. They convert to C# `using` directives over the converted opcodes.cs / runner.cs namespaces — no external NuGet.
- Authoritative basis: identical decision recorded in `.codeconv/conversion-specs/lib/bytecode/runner.dart.md` lines 77–115 for the same package layer (`rf-dart-import-relative-to-csharp-using-namespace`). FR-024 cache hit — NO new research call.

### rf-dart-final-field-class-to-csharp-getonly-class — LintIssue / LintResult (cache hit)

- Deep analysis: LintIssue has three `final` fields (String code, String message, int index) populated by a positional constructor and never reassigned — the canonical Dart immutable-record-class shape. LintResult holds a `final List<LintIssue>` (final REFERENCE, mutable contents) plus a computed `bool get ok => issues.isEmpty`.
- Authoritative basis: idiom established in `.codeconv/conversion-specs/lib/compiler/token.dart.md` and reused in `lib/bytecode/opcodes.dart.md`. Decision: reference-type C# class with get-only auto-properties (NOT record-struct — both classes are stored in lists and inspected by reference, and LintIssue has a polymorphic ToString override). FR-024 cache hit — no new research call. `Index` widens to `long` per `rf-dart-int-to-csharp-long-width` (opcodes.dart.md cache).

### rf-dart-pattern-match-cascade-dispatch-to-csharp-is-pattern-cascade — local predicate + main loop (cache hit)

- Deep analysis: the local `isHeadGuardOp` predicate is a disjunction of seven `op is X` runtime type-tests; the main `for` loop body is a longer cascade of `if (op is X) { ...; continue; }` arms driving a four-state machine. Both shapes are the canonical pattern-match-cascade-dispatch idiom.
- Authoritative basis: idiom established in `.codeconv/conversion-specs/lib/bytecode/runner.dart.md` (lines 476–534, 1462–1475). Microsoft Learn — pattern matching (https://learn.microsoft.com/en-us/dotnet/csharp/language-reference/operators/patterns) documents the `is` type-pattern as the C#-idiomatic runtime type-test + binding; Dart `is` (https://dart.dev/language/operators#type-test-operators) provides the same semantic. Codegen MUST preserve ARM ORDER for the main-loop state machine (Label early-continue first, post-SuspendEnd second, !inClause third, head/body split last) — reordering would silently change which LintIssue codes fire. FR-024 cache hit — no new research call.
- Local-function nuance: the Dart local function `bool isHeadGuardOp(Op op) => ...` is rendered as a C# `static` local function (no captured locals), avoiding the delegate-allocation overhead a `Func<Op,bool>` lambda would impose.

### rf-dart-iterable-where-to-linq — list literal + final whereType count (cache hit)

- Deep analysis: `<LintIssue>[]` initialises a growable typed list; `issues.add(...)` mutates in place; `p.ops.whereType<SuspendEnd>().length` performs a runtime-type-filter + count.
- Authoritative basis: idiom established in `.codeconv/conversion-specs/lib/analysis/analysis_phase.dart.md`. Microsoft Learn — `Enumerable.OfType<TResult>` (https://learn.microsoft.com/en-us/dotnet/api/system.linq.enumerable.oftype) documents the .NET counterpart of Dart `Iterable.whereType<T>()` — both filter by runtime type and skip non-T elements. `.length` on the filtered Iterable becomes `.Count()` (terminal that walks the deferred sequence). Codegen MAY substitute `Count(o => o is SuspendEnd)` (single-pass, no allocation) but `OfType<SuspendEnd>().Count()` is the more LITERAL translation — preferred for review traceability. FR-024 cache hit — no new research call.

### rf-dart-runtimetype-in-interpolation-to-csharp-gettype-name — diagnostic messages (NEW)

- Deep analysis: four LintIssue messages interpolate `\${op.runtimeType}` into a human-readable diagnostic. Dart `Object.runtimeType` returns the runtime Type token; its `toString()` yields the unqualified class name (e.g. `ClauseTry`), and that string-form is what flows into the interpolated message.
- Authoritative Dart: dart.dev language reference — `Object.runtimeType` (https://dart.dev/language/operators and the dart:core Object documentation) — returns the dynamic type of the object; its string-form is the unqualified class name by convention.
- Authoritative .NET: Microsoft Learn — `System.Type.Name` (https://learn.microsoft.com/en-us/dotnet/api/system.type.name) returns the simple name of the type without namespace; `Type.FullName` is the alternative that INCLUDES the namespace. For diagnostic readability the simple `Name` matches Dart's convention.
- Single research call (first time this construct appears in feature 018's spec corpus); cached as `rf-dart-runtimetype-in-interpolation-to-csharp-gettype-name` for future reuse. Authoritative on both sides — no escalation.
