# Implementation Plan: GLPnet Gleam Capability Delivery

**Feature:** `101-gleam-capability-delivery` · **Branch:** `101-gleam-capability-delivery`
**Spec:** [spec.md](spec.md) · **Plan date:** 2026-09-03 · **Size:** maxi / 17 points

## Summary

Make glpnet's existing, parity-proven Gleam/BEAM GLP capability **deliverable to two sibling rings at
once** without breaching the YNGENIOS lattice: a **runtime-free contract** both rings satisfy, plus
**one realization per runtime** — BEAM/Erlang for the Windows+Linux workstation (L1b), Gleam-on-AtomVM
for the MAUI Blazor Hybrid app channel (L1a, binding at L2).

The capability already exists and works: **206/206 corpus parity, 0 divergences, 0 excused**, and it
is **build-independent of the Dart runtime** (`gleam.toml` declares only `gleam_stdlib` +
`gleam_erlang`). So this is **not** a port. The work is the **seam and the evidence**: extract the
contract, add the AtomVM-subset refusal, and build per-ring conformance reporting that cannot report
a pass for a ring it did not build.

**Guidance applied** (`refine resolve plan`): *prefer the simplest design that satisfies the spec*;
*call out constraints and rejected alternatives explicitly*.

## Phase 0 — Research

**Output:** `research.md`. Three questions, each already part-answered by measurement:

1. **AtomVM supported subset** — what must the refusal (FR-004) enumerate? Seed: the existing F1
   dossier decision to exclude `gleam_otp` for `proc_lib`. *Decision needed:* build-time rejection vs
   runtime. **Build-time**, because a runtime rejection is a silent degrade under FR-004.
2. **Contract extraction boundary** — which of the ~83 modules are runtime-free today? Measurable by
   import analysis; nothing is assumed.
3. **Headful verification for the app ring** — with no host present, what is the strongest honest
   evidence? Likely a subset-conformance + probe result, reported as **UNREAD for the host**, never
   as a pass (SC-006).

## Complexity Tracking

| risk | mitigation |
|---|---|
| **Aggregate hides an unbuilt ring** — the single most likely way this feature ships a lie | FR-008 + SC-006: per-ring reporting; a positive control builds one ring only and asserts the aggregate refuses |
| **The AtomVM host does not exist**, so US2 cannot be fully demonstrated here | Keep US2 at P2; report host-side as **UNREAD with a named reason**, never as pass. Do not synthesize a host to make a suite green |
| **Contract extraction drags a runtime dep into L0** | SC-004 positive control introduces one and asserts the build fails |
| **A conformance harness that cannot fail** — this repo's recorded defect class, four instances | SC-003 mutation gate: a no-op guard must turn the suite RED. Write the mutation test **before** the guard |
| **Parity corpus mistaken for total equivalence** | Assumption 3 states the 206/384 gap; every report carries its denominator (FR-006) |
| Concurrent-session `git add -A` sweeping this feature's files | Principle VII: stage by name only |
