# Research — codeconv-codegen (Phase 0)

All decisions trace to the clarified spec (Session 2026-05-23) and the 012–018 mechanisms. Format: Decision / Rationale / Alternatives.

## R1 — (C) hybrid topology
- **Decision**: Two halves. Production `tools/codegen/` (deterministic, auto-discovered, in the durable pipeline) spawns harness codegen sub-agents that emit `.cs`; an offline `tools/codegen_opt/` runs DSPy+GEPA. The only production coupling is a checked-in optimized-prompt artifact (`.codeconv/codegen-prompt/optimized.md`).
- **Rationale**: Satisfies "GEPA/dspy actively" while preserving the cross-pipeline R3 invariant (production/durable path deterministic, replay-safe, LM-free). Clarification Q1.
- **Alternatives**: (A) in-package optimizing LM on the durable path — rejected (replay-safety, secret/network). (B) no GEPA — rejected (drops the requirement).

## R2 — DSPy program + GEPA wiring
- **Decision**: `codegen_opt/program.py` defines a `dspy.Module` with a signature `(plan, convspec, dependency_interfaces, idioms) -> csharp`. `optimize.py` runs `gepa` (reflective Pareto) over a held-out set with `metric.py`, bounded by a `--budget`/max-metric-calls cap; serializes the best instructions to the prompt artifact (`export-prompt`).
- **Rationale**: DSPy/GEPA are the installed, requested optimizer; the optimized *instructions* (not weights) are portable to the harness codegen sub-agent.
- **Alternatives**: MIPRO/BootstrapFewShot — GEPA was explicitly requested; others optional later.

## R3 — Replay-safe codegen DBOS step
- **Decision**: `codegen` step body = read the checked-in `.cs` for the file, run `dotnet build` (and `dotnet test` in Inc-2), record build/test result + escalations into `dart_codegen`; if `.cs` absent return `{"needs_agent_work": True, ...}` (typed sentinel, never raise). The skill catches the sentinel, spawns the codegen sub-agent (which writes `.cs`), then re-drives.
- **Rationale**: Verbatim convspec R3 pattern (018); replay re-reads the artifact, never re-calls a model.
- **Alternatives**: raise on missing artifact — rejected (DBOS records a failed step).

## R4 — Build/test feedback harness
- **Decision**: `buildgate.py` shells `dotnet build <project> -clp:ErrorsOnly` (and `dotnet test` Inc-2), parses pass/fail + error list deterministically. Each generated batch builds incrementally against already-generated dependency assemblies.
- **Rationale**: `dotnet 10.0.200-preview` is present; build success is the hard gate (FR-003). Topo order makes per-batch builds cheap.
- **Alternatives**: Roslyn in-process — heavier, no benefit over the CLI for a gate.

## R5 — Codegen-readiness + batching
- **Decision**: `readiness.py` (pure) selects the next batch as files whose every cross-SCC dependency is `codegen`-complete, SCC = one indivisible batch — the same predicate shape as convspec/planagents readiness over the 015 depgraph. `next --limit N`.
- **Rationale**: dependency-before invariant (FR-002) so each batch compiles against generated deps. Reuses 015 read-only.
- **Alternatives**: flat alphabetical — rejected (breaks build-against-deps).

## R6 — Composite metric + human-review gate
- **Decision**: build pass = hard gate (floor on fail). Compiling-candidate score = `0.6·test_pass_rate + 0.4·norm(human 1–5)`; pre-tests (Inc-1) = `norm(human)`. Human review batch-sampled `max(3, 20%)`, 1–5 + free-text. Promotion gate = 100% build + human median ≥ 4/5. Free-text feeds GEPA reflectively.
- **Rationale**: Clarification Q2 verbatim.
- **Alternatives**: build-only metric — rejected (drops human/test signal the user required).

## R7 — Optimized-prompt artifact
- **Decision**: `.codeconv/codegen-prompt/optimized.md` — serialized optimized instructions + provenance (optimizer version, metric score, dataset hash, timestamp). `prompt.py` loads it for the production sub-agent; checked in; idempotent (only regenerated by `codegen-opt export-prompt`).
- **Rationale**: the single, auditable production input from the offline optimizer (R1).
- **Alternatives**: DSPy pickle — rejected (not human-reviewable; brittle across versions).

## R8 — Idiom-KB + conventions in the codegen context
- **Decision**: the codegen sub-agent prompt includes the file's convspec + plan + the conversion-idiom KB rows + already-generated dependency public surfaces, and MUST honor recorded conventions (`*Error` names retained; `getX→LookupX`).
- **Rationale**: FR-011; consistency with ratified plans/convspecs.
- **Alternatives**: source-only — rejected (re-derives decisions already ratified).

## R9 — Codegen schema + migration linearization
- **Decision**: `dart_codegen` two-phase table; `0007_codegen.py` (`down_revision="0006"`); CREATE TABLE IF NOT EXISTS; `codeconv` schema only; single head.
- **Rationale**: FR-013; mirrors `dart_plans`/`dart_convspecs`; 018 head is `0006`.
- **Alternatives**: reuse `dart_plans` — rejected (distinct lifecycle/columns).

## R10 — LM backend resolution
- **Decision**: optimizer uses OpenAI via litellm; model from `--model`/env (default the strongest available OpenAI reasoning model); `OPENAI_API_KEY` from env, read only in `codegen_opt`. Production sub-agents run on the Claude Code harness (no OpenAI on the production path).
- **Rationale**: Clarification Q3; only OpenAI+litellm are installed (no anthropic SDK); IP exposure is the accepted offline-only tradeoff.
- **Alternatives**: anthropic SDK — not installed; would add a dependency.

## R11 — Cost/IP + generated-tree git policy (OPEN — top analyze item)
- **Decision (proposed)**: GEPA hard budget cap (flag, conservative default). **OPEN**: whether `out/csharp/` generated code is committed (reviewable, diffable) or gitignored as regenerable output. Proposed default: **commit it** (it is reviewed, build-gated product, parallel to checked-in convspecs/plans), with the optimizer/state dirs ignored.
- **Rationale**: budget cap prevents runaway (SC-006). The git policy is a genuine fork affecting review/repo-size; flagged for `/buildkit-analyze` + human gate (parallels 018's DBOS-activation gate).
- **Alternatives**: gitignore `out/csharp/` (treat as build output) — viable; deferred to the gate.

## R12 — Crash/SCC semantics + durable-builder integration
- **Decision**: add a `codegen` stage AFTER `plan` in the 018 per-file/SCC child workflow; SCC = one indivisible codegen unit; crash mid-file resumes at the interrupted stage; deterministic re-drive. Generated `.cs` ingest is content-addressable enough that re-drive finds the artifact and completes.
- **Rationale**: 018 R13 carry-forward; consistent durability.
- **Alternatives**: standalone non-durable codegen runner — rejected (loses 018 resumability/trace).
