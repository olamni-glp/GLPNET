# Phase 1 Data Model: HTTP/3 (QUIC) + WebSocket Channel-Link Prototype

**Feature**: 036-http3-quic-ws-link | **Date**: 2026-06-27

Entities, the wire/message contract, the handshake, and the link state machine. Derived directly from the spec's
Key Entities + Requirements; the link-layer reliability semantics (sequencing, dedup, fencing, backpressure,
ground-relay) are **inherited from spec 025** and referenced, not redefined here (FR-018, constitution VIII).

---

## Entities

### Server instance
A long-running `glp-quick --server` process.
- **Fields**: `bind_addr` (LAN IP or machine name), `udp_port`, `stack` (`csharp` | `gleam`), `cert_ref`
  (shared-cert path), `max_clients` (≥3, configurable — FR-011), `sessions` (set of Client sessions).
- **Rules**: binds one UDP port for QUIC; holds the shared cert; accepts up to `max_clients`; behaviour beyond
  the ceiling is **defined** (reject-with-clear-error vs queue — chosen in contracts, not left undefined — edge case).
- **State**: `starting → listening → serving(n) → draining → stopped`.

### Client instance
A `glp-quick --client` process.
- **Fields**: `server_addr` (IP/name), `udp_port`, `stack`, `cert_ref` (the same shared cert to trust), `link` (its Link).
- **Rules**: trusts only the shared cert by fingerprint (no CA/hostname); fails clearly (or retries) if the
  server is not yet ready (edge case); one client's failure must not affect others (FR-006/SC-004).
- **State**: `connecting → handshaking → linked → closed | failed`.

### QUIC connection / stream
The genuine HTTP/3 transport between a client and the server (RFC 9000/9001/9002 + RFC 9114).
- **Fields**: `conn_id`, `alpn` (HTTP/3), `peer_cert_fingerprint`, `streams` (multiplexed).
- **Rules**: established by a real on-wire handshake (FR-001 — NOT loopback); ALPN/version mismatch is rejected
  cleanly, never half-open (edge case, FR-019); one bidirectional stream carries the WebSocket per link.

### WebSocket link
The framed message channel layered over the QUIC connection: **genuine RFC 6455 framing over one QUIC
bidirectional stream** (one WS per stream — the carriage RFC 9220 standardizes), reusing 025's `FrameCodec`,
established by a minimal CONNECT-style bootstrap on the stream. The RFC 9220 Extended-CONNECT-over-HTTP/3 bootstrap
(unshipped in .NET) is isolated behind a seam for later third-party/browser interop only.
- **Fields**: `link_id` (025 `LinkId`), `role` (025 `LinkRole` — independent of data direction), `epoch`
  (025 fencing), `send_window` (025 backpressure N), `seq`/`ack` (025 sequencing).
- **Rules**: full-duplex (FR-008a); reliable, ordered, idempotent redelivery and bounded backpressure are
  **provided by spec 025's reliability sublayer** — not reimplemented; faults surface on the 025 monitor stream
  as ordinary bound terms (`ok`/`closed`/`tempFail`/`permFail`), never a special verdict.

### Shared certificate
The self-signed certificate + key generated by the Python tool — the **only** trust anchor.
- **Fields**: `fingerprint` (SHA-256), `not_before`/`not_after`, `key` (private, server-side only), `pem` (public).
- **Rules**: generated by `glp-quick cert` (FR-003); distributed out-of-band; both ends trust **by fingerprint**;
  no domain/SAN/CA used for trust (SC-005); mismatch/rotation rejected with a clear, non-ambiguous failure (edge case).

### GLP REPL endpoint
A running GLP REPL participating in the link as a message sender and/or receiver; in the mesh case, a peer.
- **Fields**: `endpoint_id`, `repl_kind` (`csharp` default | `dart`), `inbox`, `outbox`, `peers` (mesh).
- **Rules**: bridged to a Link endpoint by `repl_link.py`; can send and receive concurrently (FR-008a); in the
  mesh, can reach every other participating REPL (FR-008b).

### GLP message
A unit of data emitted by one REPL endpoint and delivered to one or more receiving REPL endpoints.
- **Fields**: `msg_id`, `from` (endpoint_id), `to` (endpoint_id | `broadcast`), `payload` (a **ground** GLP term — 025 ground-relay), `seq`.
- **Rules**: only ground terms cross the wire (025 discipline — no `_w`/`_r` placeholders); delivered reliably,
  in order, exactly once (025 dedup); routed peer-to-peer in the mesh.

### Stack adapter
A transport implementation (C#/.NET, or Gleam in deployment Profile A or C) behind the common CLI/contract.
- **Fields**: `name` (`csharp` | `gleam`), `profile` (`a` | `c`, gleam only), `launch_cmd`, `health`,
  `capabilities` (`real_quic: bool`, `quic_termination`: `in_process` | `side_process`).
- **Rules**: all drivable through the identical `glp-quick` surface and wire contract (FR-010), interchangeable
  **at the channel-link contract** (not at QUIC termination); `csharp` is the cross-platform reference (must reach
  the full real-QUIC demo first); `gleam` Profile A attributes `real_quic` to a native side-process and Profile C
  terminates QUIC in-process — both reported honestly (Decision 8, constitution II).

### Research source / Distillation note
A catalogued corpus entry and its close-read architectural findings (FR-014/FR-015).
- **Fields**: `source_id`, `stack` (`csharp` | `gleam` | `rfc`), `url`/`ref`, `rfc` (9114/9000/9001/9002/9220 if applicable),
  `concern` (handshake/alpn/cert/streams/ws/backpressure/concurrency/failure), `distillation` (close-read note), `informs` (FR/SC ids).
- **Rules**: ~50 per stack; each note is a close read, not a summary (SC-007); stored under `research/`.

## Wire / message contract (summary — full form in `contracts/wire-contract.md`)

1. **Transport**: QUIC (RFC 9000) + QUIC-TLS (RFC 9001), loss/cc per RFC 9002. ALPN = HTTP/3 (`h3`).
2. **Application**: HTTP/3 (RFC 9114).
3. **Link bootstrap**: genuine RFC 6455 WebSocket framing over one bidi QUIC stream (025 `FrameCodec`), via a
   minimal CONNECT-style bootstrap on the stream. RFC 9220 Extended-CONNECT-over-HTTP/3 isolated behind a seam (later interop only).
4. **Trust**: shared self-signed cert, accepted by SHA-256 fingerprint only (no CA/hostname).
5. **Message framing**: spec 025 framing (version + CRC32 + fragment) carrying ground GLP terms; sequencing,
   dedup, reorder, epoch/fencing, and a backpressure window of N — all inherited from 025.
6. **Routing**: `from`/`to`/`broadcast`; the server multiplexes a duplex mesh across concurrent client links (FR-008b).

## Handshake (server A ↔ client B)

```
B: QUIC Initial (ALPN h3) ──────────────▶ A
A: TLS 1.3 cert = shared self-signed  ──▶ B   (B verifies by fingerprint, not chain/hostname)
B: (SPKI-pin match) ─ completes 1-RTT handshake ─ QUIC connection up (ALPN h3)
B: minimal CONNECT-style bootstrap on a bidi QuicStream ▶ A   → genuine RFC 6455 WebSocket link up on that stream
A/B: 025 link epoch/seq init → linked; GLP messages flow full-duplex
```
- Cert mismatch → handshake rejected, clear error (no half-open). ALPN/version mismatch → clean reject.
- UDP blocked → detected and reported, not hung (edge case). Server-not-ready → client fails clearly or retries.

## Link state machine

```
connecting → handshaking → linked ⇄ (full-duplex message flow) → draining → closed
                  │                                                   ▲
                  └── fail (cert/alpn/udp/timeout) → failed ──────────┘ (clear error; siblings unaffected)
```

Concurrency: each client↔server pair is an **independent** Link with its own epoch/seq/window; one Link's
`failed`/`closed` transition leaves sibling Links in `linked` (FR-006/SC-004).
